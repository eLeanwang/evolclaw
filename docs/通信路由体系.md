# EvolClaw 通信路由体系

本文档定义 EvolClaw 的通信路由概念体系——从入站消息到 baseagent 对话的完整路由链路。

## 总览

一条入站消息要完成处理，需要两次路由：

```
入站消息 ──→ Agent 路由键（channelKey）──→ 找到 EvolAgent
                                              │
                                        会话路由键（sessionKey）──→ 找到 Session ──→ agentSessionId ──→ baseagent 对话
```

## Agent 路由键（channelKey）

**目的**：从入站消息定位到本端响应的 EvolAgent。

```
channelKey = channelType # selfAID # channelName
```

| 段 | 含义 | 说明 |
|----|------|------|
| `channelType` | 平台类型 | `'aun'` / `'feishu'` / `'wechat'` / `'dingtalk'` / `'qqbot'` / `'wecom'` |
| `selfAID` | 本端 agent 的 AID | 不做 urlEncode（AID 不含特殊字符）；唯一标识 agent |
| `channelName` | 渠道实例名 | 来自 `config.json` 的 `channels[].name`；同一 channelType 内唯一 |

**分隔符**：使用 `#`，因为 `#` 不在 AID 合法字符集内，天然无歧义切分。

### AUN 渠道

AUN 是 agent 的存在基础，不在 `channels[]` 中配置，从 agent 的 AID 隐式派生：

- `selfAID` = agent 自身的 AID
- `channelName` 固定为 `main`
- 因此 AUN 的 channelKey 恒为 `aun#<selfAID>#main`
- 只要知道本端 AID，就能定位到 agent

### 非 AUN 渠道

从 `config.json` 的 `channels[]` 中读取。知道 agent（通过 selfAID）后，通过 channelType + channelName 可以准确定位到 channelInstance，获取该渠道的具体参数：

| channelType | channelInstance 关键凭证字段 | 示例 |
|-------------|---------------------------|------|
| `feishu` | `appId` + `appSecret` | `cli_abc123` |
| `wechat` | `token` | `wx_token_xxx` |
| `dingtalk` | `clientId` + `clientSecret` | `ding_xxx` |
| `wecom` | `botId` + `secret` | `wk_xxx` |
| `qqbot` | `appId` + `clientSecret` | `qq_xxx` |

### 为什么用 selfAID 而不是渠道原生 selfId

channelKey 的目的是路由找到 agent。用 selfAID 直接定位 agent，不需要遍历所有 agent 的配置文件。而渠道原生的身份字段（如飞书的 appId）需要遍历才能反查到 agent。

知道 agent 之后，再通过 channelType + channelName 定位到 channelInstance，从中获取渠道原生参数。

## 会话路由键（sessionKey）

**目的**：在 agent 范围内定位到一个 Session，从而拿到 `agentSessionId` 让 baseagent 继续对话。

```
sessionKey = channelType # channelId # threadId
```

| 段 | 含义 | 说明 |
|----|------|------|
| `channelType` | 平台类型 | 同上 |
| `channelId` | 对话标识 | AUN 私聊=对端 AID；AUN 群聊=groupId；飞书=chat_id；其它渠道=原生会话 ID。需 urlEncode |
| `threadId` | 话题标识 | 无话题时固定为 `main`；飞书话题回复时为 thread_id。需 urlEncode |

sessionKey 是 **agent 内部键**（先通过 channelKey 找到 agent，再在该 agent 范围内用 sessionKey 定位 session），不是全局唯一键。

### channelId 的本质

channelId 标识"跟谁/在哪个群"的对话：

| 场景 | channelId 取值 |
|------|---------------|
| AUN 私聊 | 对端 AID |
| AUN 群聊 | groupId |
| 飞书 | chat_id |
| 其它渠道 | 该渠道的原生会话 ID |

### threadId 的作用

threadId 是 channelId 之下的子路由维度，用于支持话题/线程场景：

- 无话题时固定为 `main`（主会话），sessionKey 始终保持三段格式
- 飞书话题回复时为 thread_id
- 有非 main 的 threadId 时会创建独立的话题 session，回复路由回同一话题

## 关系层路由键（peerKey）

**目的**：定位 agent 对某个对端/群的关系数据。peerKey 是 sessionKey 的前两段，因此群聊中所有发言者共用同一个 relations 目录（对应同一个 session）。

```
peerKey = channelType # urlEncode(channelId)
```

| 段 | 含义 |
|----|------|
| `channelType` | 平台类型 |
| `channelId` | 对话标识（私聊=对端 ID，群聊=群 ID）。需 urlEncode |

**群聊语义**：群里多个人发言时，channelId = groupId，所有人共用同一个 session，因此 relations 目录也是同一个（`relations/feishu#oc_xxx/`）。这里记录的是"我与这个群/对话的关系"，而不是"我与某个具体发言者的关系"。

**数据位置**：`$AGENT_DIR/relations/<peerKey>/`

**示例**：
- AUN 私聊对端：`relations/aun#bob.aid.pub/`
- 飞书群：`relations/feishu#oc_xxx/`
- 微信对端：`relations/wechat#wxid_xxx/`

## 会话文件系统路径

```
data/sessions/<channelType>/<selfAID>/<urlEncode(channelId)>/
```

所有渠道统一三层结构：
1. `channelType` — 平台类型（不 encode）
2. `selfAID` — 本端 agent 的 AID（不 encode）
3. `urlEncode(channelId)` — 对话标识（encode）

## channelKey 的生命周期

channelKey 不是从每条入站消息中现场解析的，而是 **启动时构造、运行时直接持有** 的。

### 启动阶段

```
加载 agent config.json
  → 遍历 channels[]，为每个 channelInstance 创建 ChannelAdapter
  → adapter 创建时构造 channelKey = channelType#selfAID#channelName
  → 注册到 EvolAgentRegistry.channelIndex（channelKey → agent AID）
  → adapter 用 channelInstance 中的凭证（appId/token 等）注册 webhook 或建立长连接
```

### 运行时路由

**AUN 渠道**：消息中携带目标 AID（即 selfAID），可以直接构造 channelKey 查找。

**非 AUN 渠道**：消息到达某个 adapter，是因为该 adapter 用对应的凭证注册了 webhook/长连接。adapter 在创建时就已经绑定了 channelKey，消息能到达它本身就意味着 agent 路由已完成。

```
非 AUN 入站消息
  │
  │  消息到达 adapter（adapter 持有 channelKey）
  │  → adapter 已知 selfAID（创建时绑定）
  │  → 不需要从消息中反查 agent
  │
  ├─ adapter.channelKey → 直接路由到 EvolAgent
  │
  ├─ channelType + channelId + threadId
  │   → 构造 sessionKey
  │   → SessionManager 定位/创建 Session
  │   → 拿到 agentSessionId → baseagent 继续对话
  │
  └─ channelType + channelId
      → 构造 peerKey
      → 加载关系数据 → 注入上下文
```

### 关键区分

| | AUN 渠道 | 非 AUN 渠道 |
|--|---------|------------|
| selfAID 来源 | 消息中携带目标 AID | adapter 创建时绑定 |
| agent 路由方式 | 从消息解析 → 构造 channelKey → 查 registry | adapter 已持有 channelKey，隐式完成 |
| channelInstance 定位 | AID 隐式派生（无需 channels[]） | 通过 channelType + channelName 从 config 获取 |

## 完整路由流程（逻辑视角）

```
入站消息
  │
  ├─ channelType + selfAID + channelName
  │   → 构造 channelKey
  │   → EvolAgentRegistry.resolveByChannel(channelKey)
  │   → 找到 EvolAgent
  │
  ├─ channelType + channelId + threadId
  │   → 构造 sessionKey
  │   → SessionManager 定位/创建 Session
  │   → 拿到 agentSessionId
  │   → baseagent 继续对话
  │
  └─ channelType + channelId
      → 构造 peerKey
      → 加载 relations/<peerKey>/ 下的关系数据
      → 注入上下文
```

## 层级关系

```
channelKey:    channelType # selfAID # channelName        ← 路由到 agent（selfAID 不 encode）
                                │
                          在 agent 内部
                                │
sessionKey:              channelType # urlEncode(channelId) # urlEncode(threadId)    ← agent 内部键，路由到 session
                                │
                          session 内
                                │
                          agentSessionId                   ← baseagent 的 session

peerKey:       channelType # urlEncode(channelId)          ← 关系层数据键（= sessionKey 前两段）
                                │
                          relations/<peerKey>/
```

## 核心字段定义

| 字段 | 唯一定义 | 编码规则 |
|------|---------|---------|
| `channelType` | 平台枚举值：`'aun'` / `'feishu'` / `'wechat'` / `'dingtalk'` / `'qqbot'` / `'wecom'` | 不 encode |
| `selfAID` | 本端 agent 的 AID | 不 encode（AID 不含特殊字符） |
| `channelName` | `channels[].name`，短实例名；同一 channelType 内唯一 | 不 encode |
| `channelId` | 对端/群在该渠道的原生 ID | urlEncode |
| `threadId` | 话题 ID；无话题时固定为 `main` | urlEncode |
| `channelKey` | agent 路由键：`channelType#selfAID#channelName` | 见各段 |
| `sessionKey` | agent 内部会话键：`channelType#urlEncode(channelId)#urlEncode(threadId)` | 见各段 |
| `peerKey` | 关系层键：`channelType#urlEncode(channelId)`（= sessionKey 前两段） | 见各段 |
| `agentSessionId` | baseagent 的 session 标识 | 不是 evolclaw 的 session.id |

## 与当前代码的差异

以下是当前代码实现与本概念体系的已知偏差，需要逐步修正：

| 问题 | 现状 | 应改为 |
|------|------|--------|
| channelKey 第二段 | 一律用 `agent.aid`（`effectiveChannelName` 写死），概念上正确但变量名叫 `selfPeerId` | 变量名改为 `selfAID`，语义更清晰 |
| `channelName` 含义混用 | 有些地方存完整 channelKey，有些存短名 | 统一：`channelName` = 短名；需要完整键时用 `channelKey` |
| sessionKey 格式 | `${channel}:${channelId}`（冒号分隔，无 threadId） | `channelType#channelId#threadId`（`#` 分隔，含 threadId） |
| sessions 目录结构 | AUN 三层，其它渠道两层 | 所有渠道统一三层：`<channelType>/<selfAID>/<channelId>/` |
| peerKey 参数名 | 接口参数叫 `channel`，调用方自觉传 channelType | 参数名改为 `channelType`，拼装抽成 helper `formatPeerKey(channelType, channelId)` |
