# 待办：从设计文档提炼 agent 运行时操作手册

>
> **本文是「写作指导」，不是「内容草稿」**。设计文档（10/20/30）仍在迭代、尚未定稿，此刻写死手册内容会过时。所以这里只规定：要产出哪些手册、各自的用途与读者、提炼原则、以及定稿后如何据此生成。等设计定稿，由大模型依据本指导从最新设计文档生成手册。

---

## 1. 为什么需要这件事（设计文档 ≠ 运行时手册）

`docs/aun-fs/` 下的文档是**设计文档**——面向人类实现者，讲架构分层、能力契约、为什么这么设计、有哪些权衡。它们**不是** agent 运行时加载的上下文：

- 太长（四份近千行），全量进 system prompt 浪费 token、稀释注意力。
- 含大量「为何/权衡/现状对照/SDK 缺口」，对运行中的 agent 是噪声——agent 要的是「这个场景敲哪条命令、参数从哪来」。
- 设计文档放在 `docs/`，不在 ECK 加载范围；agent 运行时的知识文档在 `kits/docs/evolclaw/`，通过 ECK 索引按需 Read。

所以需要一层**提炼**：把「设计」蒸馏成「操作手册」，分离存放、分别演进。这与现有 `fs-architecture.md`（全景设计）vs `fs.md`（精简操作手册）的关系一致——设计与手册分离是既定模式。

## 3. 提炼原则（设计文档 → 手册的转换规则）

从设计文档生成手册时，遵循以下转换：

**保留**：
- 每个命令的**用法、参数、典型场景**（agent 运行时真正需要的）。
- **参数从哪来**——尤其「上一条命令的响应里带出了下一条的参数」这类链路（如 submit 失败响应自带 merge 所需的 base-version 与 currentTarget）。这是 agent 友好的核心，必须在手册里讲透。
- **✅/❌ 对照例子**（如 `ln -s` 真实路径在前、软链在后这种最易写反的地方）——看例子比读解释更不易错，手册里要保留并强调。
- **失败响应的样式**——让 agent 知道失败长什么样、下一步敲什么。
- **能力边界的硬限制**（如 `grep -r` 被拒、要缩小到单文件）——避免 agent 反复尝试做不到的事。

**剥离**（移入或留在设计文档，不进手册）：
- 「为何这么设计」「权衡」「与云存储对比」等论证性内容。
- SDK 能力缺口、现状对照、契约验收标准——这些是给实现者的，agent 不关心。
- 内部数据结构细节（如 `.collab-versions/` 的物理布局、台账 JSON 格式）——除非 agent 操作时必须知道；能用 collab 命令封装掉的就不暴露。
- 分层架构图、依赖方向等宏观叙述。

**改写**：
- 视角从「设计者解释系统」改为「**对 agent 下达操作指引**」——祈使句、场景驱动、命令先行。
- 省略 `--as`（运行时 daemon 已注入 `EVOLCLAW_SELF_AID`），仅跨身份操作时提一句可显式带——与现有手册惯例一致。
- 按**场景**组织（「想发布文件 → 这样做」），而非按命令字母序罗列。

## 4. 手册必须覆盖的关键场景（来自设计中已验证顺畅/易错的点）

定稿生成时，确保这些在我们讨论中反复出现的关键链路被手册讲清：

- **发现并参与协作**：find/卡片 → `collab ls` 拿文档清单（不要让 agent 裸 `fs ls` 认 `@current` 后缀）→ read → 编辑 → submit。
- **submit 撞版本 → merge → 重提**：强调失败响应自带 base-version 与 currentTarget，参数无需 agent 拼接。
- **对外发布/分享**：`ln -s` 进 `/public` + chmod/token，含 ✅/❌ 方向例子。
- **目录快照与回滚**：create（自动算 bump）/ restore（非破坏、forward-only）/ prune。
- **备份与换 host**：export / adopt 的用途与何时用。
- **群里两层授权**：成员挂载要「卷主 setfacl + 群 admin approve」两步，缺一不可；两种失败的报错区分（EACCES vs 不在群内）。
- **能力边界**：哪些命令做不了/很贵（grep -r、原地编辑），手册要明示替代路径。

## 5. 执行前提与流程（定稿后）

1. **前提**：设计文档 10/20/30 定稿（命令集、参数、授权模型、快照/export 语义不再大改）。
2. **核对**：生成前通读最新设计文档，以设计文档为准——本指导只规定「怎么提炼」，不规定「写什么命令」，命令以定稿设计为唯一事实源。
3. **生成**：按第 2 节产物清单、第 3 节提炼原则、第 4 节场景清单，逐份写到 `kits/docs/evolclaw/`。
4. **索引**：手册写完后更新 `kits/docs/evolclaw/INDEX.md`（ECK 命令集目录），加入新手册的触发词与路径，使 agent 能按需定位。
5. **交叉检查**：确保手册与 `kits/rules/06-channel.md` 的命令集总览表一致（该表已列 `ec storage`/`ec group` 等，新增 `ec fs`/`ec collab` 需同步）。
