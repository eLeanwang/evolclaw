## 需要先拍板的 5 个问题

1. 数据源：先用 API-Football，还是直接用 Sportmonks All-In？
2. 认证：MVP 用参赛 token，还是一开始就做 AID 签名 HTTP？
3. 淘汰赛玩法：继续猜胜平负，还是猜晋级球队？
4. 胜率：只展示，还是参与积分加成？
5. 站点形态：独立网站，还是集成到现有 EvolClaw Web？

我的默认建议：

- 数据源先用 API-Football。
- Agent 和人类先统一用 token 参与。
- MVP 全部比赛先用胜平负 + 可选比分。
- 胜率只展示，不参与积分。
- 先做独立网站，避免污染 EvolClaw 核心。

### M3：数据源接入

目标：同步真实世界杯数据。

任务：

- [ ] 定义统一 `FootballDataProvider` 接口。
- [ ] 实现 API-Football provider。
- [ ] 同步球队、场地、赛程、小组/阶段。
- [ ] 同步比赛状态和最终比分。
- [ ] 同步赔率/胜率快照。
- [ ] 记录每次同步结果和错误。

验收：

- 相同数据重复同步不产生重复比赛。

### M4：竞猜 API

目标：人类和 Agent 都能通过 HTTP 提交竞猜。

任务：

- [ ] 参赛 token 生成和校验。
- [ ] `GET /api/fixtures`。
- [ ] `GET /api/fixtures/:id`。
- [ ] `POST /api/predictions`。
- [ ] `PATCH /api/predictions/:id`。

### M5：积分结算

## API 优先级

第一批必须有：

- `GET /api/health`
- `GET /api/fixtures`
- `GET /api/fixtures/:id`
- `POST /api/predictions`
- `GET /api/me/predictions`
- `GET /api/leaderboard`

第二批：

- `PATCH /api/predictions/:id`
- `POST /api/admin/sync/fixtures`
- `POST /api/admin/matches/:id/settle`
- `GET /api/admin/sync-runs`

第三批：

- `POST /api/admin/sync/odds`
- `POST /api/admin/matches/:id/override`
- `POST /api/admin/participants/:id/revoke-token`

## 风险

- 数据源收费和限流：需要先确认预算和 key。
- 世界杯赛程/开球时间可能调整：必须定时同步，不能只 seed 一次。
- 赔率/胜率不是赛果：展示时要标明来源和更新时间。
- 淘汰赛玩法容易歧义：必须提前确认按 1X2 还是晋级球队。
- Agent 认证如果一开始做 AID 签名，会拖慢 MVP；建议先 token。
