# EvolClaw Init QR Owner Binding Design

## 1. Goal

`evolclaw init` and `evolclaw init aun` bind owners through Evol App QR scanning instead of asking the user to manually type an owner AID.

The current MVP uses the already-created control daemon AID to receive the binding request:

1. CLI ensures `evolclaw.json.aid` exists.
2. CLI starts or reuses the daemon.
3. CLI asks daemon over local IPC to create an in-memory bind task.
4. CLI renders a QR code.
5. Evol App scans the QR code and sends `bind.request` to `daemonAid`.
6. daemon verifies the one-time `token` and uses the AUN envelope `from` as owner AID.
7. daemon writes `owners`.

No temporary AUN network is needed. The control daemon AID is the receiver from the start.

## 2. Field Naming

External QR and AUN payloads use these AID fields:

| Field | Meaning |
| --- | --- |
| `daemonAid` | Control daemon AID and AUN message receiver. Always present. |
| `agentAid` | Target agent AID. Present only for `bindType: "agent"`. |

## 3. Token And Task ID

`taskId` remains internal to local daemon/CLI IPC only:

- returned by IPC `bind.begin`
- used by CLI polling `bind.status`
- used by CLI cancellation `bind.cancel`
- never included in QR data
- never included in AUN `bind.request`
- never included in AUN `bind.response`

External protocol uses `token` as the only one-time binding credential. daemon stores only `sha256(token)` in memory and resolves the task by token hash.

Current token format:

- generated by `crypto.randomBytes(12).toString('base64url')`
- 12 bytes = 96 bits entropy
- 16 URL-safe characters
- one-time use
- default 10 minute TTL
- not logged and not persisted

96 bits is enough for a short-lived QR credential and keeps the QR payload smaller.

## 4. Daemon Lifecycle

The MVP distinguishes two daemon modes:

| Mode | When Used | Behavior |
| --- | --- | --- |
| normal daemon | existing daemon, or agents already exist | Full daemon runtime; binding updates owners in-place. |
| bootstrap daemon | first init and no agents exist | Control AID + IPC + bind service only. |

Bootstrap daemon is not hot-upgraded to normal mode. After binding completes, is cancelled, or times out, CLI stops the bootstrap daemon it started. Later `evolclaw start` launches the normal daemon.

Reason: in-process bootstrap-to-normal switching would require reliably constructing all normal daemon components after partial startup. That adds lifecycle risk across Linux/macOS/Windows. Restarting the process is simpler and more predictable for MVP.

Stop sequence:

1. read daemon PID from IPC `status`
2. graceful stop through cross-platform process utility
3. wait for exit
4. force kill on timeout
5. run `cleanupInstances()`
6. re-check whether old PID still responds on IPC and warn if needed

## 5. Empty Owners Safety

First init starts with empty `owners`. That is allowed only under restricted behavior:

- allow local IPC: `ping`, `status`, `bind.begin`, `bind.status`, `bind.cancel`
- allow AUN `bind.request`
- reject remote process control
- reject remote agent management
- reject remote config/log access
- never let remote AUN create binding tasks

`bind.begin` is local IPC only and relies on the local socket/named-pipe boundary.

## 6. Binding Scenarios

| Scenario | Entry | QR Fields | Config Written |
| --- | --- | --- | --- |
| daemon owner | `evolclaw init` | `daemonAid` | `evolclaw.json.owners` |
| daemon owner | `evolclaw init aun`, select daemon | `daemonAid` | `evolclaw.json.owners` |
| agent owner | `evolclaw init aun`, select agent | `daemonAid`, `agentAid`, `agentName` | `agents/<agentAid>/config.json.owners` |
| agent owner after create | `evolclaw agent new <agentAid>` | `daemonAid`, `agentAid`, `agentName` | `agents/<agentAid>/config.json.owners` |

`evolclaw init aun` is the unified owner binding entry. There is no separate `evolclaw agent bind-owner` command in the MVP.

## 7. QR Payload

QR content is a JSON string.

Daemon owner QR:

```json
{
  "type": "evolclaw.bind",
  "version": "3.4.0",
  "platform": "linux",
  "bindType": "daemon",
  "daemonAid": "ec42857.agentid.pub",
  "token": "Lx7q8LR3mV3DRXoR",
  "expiresAt": 1781720000000
}
```

Agent owner QR:

```json
{
  "type": "evolclaw.bind",
  "version": "3.4.0",
  "bindType": "agent",
  "daemonAid": "ec42857.agentid.pub",
  "agentAid": "mybot.agentid.pub",
  "agentName": "mybot",
  "token": "QtxC5x1RKoW3oW51",
  "expiresAt": 1781720000000
}
```

Fields:

| Field | Required | Description |
| --- | --- | --- |
| `type` | yes | Fixed value `evolclaw.bind`. |
| `version` | yes | EvolClaw software version for display/troubleshooting. |
| `platform` | no | EvolClaw daemon host OS: `windows`, `macos`, or `linux`; currently present only in daemon QR. |
| `bindType` | yes | `daemon` or `agent`. |
| `daemonAid` | yes | AUN receiver for `bind.request`. |
| `agentAid` | agent only | Agent owner binding target. Omitted for daemon binding. |
| `agentName` | no | UI display name for agent binding. |
| `token` | yes | 16-char one-time credential. |
| `expiresAt` | yes | Unix epoch milliseconds. |

## 8. AUN Protocol

### 8.1 bind.request

Evol App sends this JSON payload to `daemonAid`.

Example:

```json
{
  "type": "bind.request",
  "bindType": "agent",
  "token": "QtxC5x1RKoW3oW51",
  "clientName": "Alice",
  "deviceName": "Alice iPhone",
  "platform": "ios",
  "appVersion": "1.0.0",
  "timestamp": 1781719700000
}
```

Rules:

- no `taskId`
- no `clientAid`; daemon uses AUN envelope `from`
- no `agentAid`; daemon resolves target from the token-bound task
- no `ownerMode`; only local CLI can choose append/replace
- optional `deviceName` identifies the App device that scanned the QR; daemon currently accepts it but does not store or return it
- optional `platform` identifies the App device OS; daemon currently accepts it but does not store or return it
- send encrypted when supported
- do not persist the binding message into chat history when supported

### 8.2 bind.response

daemon replies to the App with JSON.

Success response fields:

| Field | daemon | agent | Description |
| --- | --- | --- | --- |
| `type` | yes | yes | Fixed value `bind.response`. |
| `bindType` | yes | yes | `daemon` or `agent`. |
| `success` | yes | yes | `true` on success. |
| `daemonInfo.daemonAid` | yes | yes | Control daemon AID. |
| `daemonInfo.agentAid` | no | yes | Bound agent AID. |
| `daemonInfo.bindType` | yes | yes | Same value as top-level `bindType`. |
| `daemonInfo.version` | yes | no | EvolClaw software version. |
| `daemonInfo.platform` | yes | no | EvolClaw daemon host OS, not App device OS. |
| `daemonInfo.uptime` | yes | no | daemon uptime in seconds. |
| `daemonInfo.baseagents` | yes | no | Baseagent CLI list currently detected on the daemon host. |
| `daemonInfo.active_baseagent` | no | yes | Agent active baseagent; fallback is `claude`. |
| `daemonInfo.model` | no | no | Agent active baseagent model; omitted when not configured. |
| `daemonInfo.effort` | no | no | Agent active baseagent effort/reasoning; omitted when not configured. |
| `daemonInfo.channels` | no | yes | Sanitized summaries of explicitly configured agent channels. |
| `daemonInfo.agentName` | no | no | Optional agent display name for agent binding. |

`channels` contains only `{ type, name, enabled }`. It excludes implicit AUN and all channel credentials.

Daemon owner success:

```json
{
  "type": "bind.response",
  "bindType": "daemon",
  "success": true,
  "daemonInfo": {
    "daemonAid": "ec42857.agentid.pub",
    "bindType": "daemon",
    "version": "3.4.0",
    "platform": "linux",
    "uptime": 42,
    "baseagents": ["codex"]
  }
}
```

`baseagents` is a runtime host scan result. The current implementation checks whether `claude`, `codex`, and `gemini` exist on `PATH`. It is not derived from EvolClaw baseagent config and does not prove account login, model access, or API readiness.

Agent owner success:

```json
{
  "type": "bind.response",
  "bindType": "agent",
  "success": true,
  "daemonInfo": {
    "daemonAid": "ec42857.agentid.pub",
    "agentAid": "mybot.agentid.pub",
    "bindType": "agent",
    "active_baseagent": "codex",
    "model": "gpt-5.4",
    "effort": "medium",
    "channels": [
      { "type": "feishu", "name": "work", "enabled": true },
      { "type": "wechat", "name": "wx", "enabled": false }
    ],
    "agentName": "mybot"
  }
}
```

Failure:

```json
{
  "type": "bind.response",
  "bindType": "daemon",
  "success": false,
  "error": {
    "code": "TASK_EXPIRED",
    "message": "binding task expired"
  }
}
```

## 9. Local IPC

CLI and daemon reuse existing IPC. No new socket and no task file are added.

| OS | Path |
| --- | --- |
| Linux/macOS | `$EVOLCLAW_HOME/data/instance/evolclaw.sock` |
| Windows | `\\.\pipe\evolclaw-<hash>` |

IPC commands and key fields:

| Command | Fields |
| --- | --- |
| `bind.begin` | `bindType`, optional internal `targetAid`, optional `agentName`, optional `ownerMode`, optional `ttlMs` |
| `bind.status` | internal `taskId` |
| `bind.cancel` | internal `taskId` |

`bind.begin` returns internal `taskId`, external `qrData`, and `expiresAt`. `qrData` does not include `taskId`.

Commands:

- `{ type: 'bind.begin', ... }`
- `{ type: 'bind.status', taskId }`
- `{ type: 'bind.cancel', taskId }`

## 10. Daemon Validation

On AUN `bind.request`:

1. parse JSON and verify `type === "bind.request"`
2. require `token`
3. hash token and find in-memory task
4. verify `payload.bindType === task.bindType`
5. verify task is pending and not expired
6. timing-safe compare token hash
7. verify AUN envelope `from` is present
8. daemon binding writes `evolclaw.json.owners`
9. agent binding verifies `agents/<agentAid>/config.json` exists and writes that owner list
10. mark task bound
11. send `bind.response`

The owner AID always comes from AUN envelope `from`, not from payload fields.

## 11. Owner Policy

Default mode is append with de-duplication:

- empty owners: write `[fromAid]`
- existing owners without `fromAid`: prepend `fromAid`
- existing owners with `fromAid`: idempotent success

Replace mode is local CLI only, for example `evolclaw init aun --replace`.

MVP wiring currently uses append. The protocol and core service already have `ownerMode` for replace, but remote App cannot choose it.

## 12. Permissions

Daemon owner:

- can control process-level EvolClaw capabilities exposed over AUN
- can manage agent lifecycle where supported
- can inspect daemon status where supported
- does not gain local shell, SSH, or arbitrary file access
- does not automatically become every agent's owner

Agent owner:

- can talk to that agent over AUN
- can use that agent's owner-only capabilities
- cannot control daemon process
- cannot manage other agents
- cannot edit `evolclaw.json.owners`

## 13. Task Lifecycle

Tasks are memory-only:

- no `bind-tasks.json`
- no runtime task file
- lost on daemon restart or crash
- CLI reports task missing and asks user to regenerate QR

Cleanup:

- interval every 60 seconds
- cancelled tasks are deleted
- expired tasks are marked expired and later deleted
- bound tasks are retained briefly for CLI polling and later deleted
- task map capped to a small bounded size

## 14. Evol App Flow

1. parse QR JSON
2. require `type`, `bindType`, `daemonAid`, `token`, `expiresAt`
3. if `bindType === "agent"`, require `agentAid`
4. reject expired QR locally
5. show confirmation UI
6. check local duplicate by `bindType + daemonAid` for daemon or `bindType + agentAid` for agent
7. send `bind.request` to `daemonAid`
8. wait for `bind.response` from `daemonAid`
9. save only after `success === true`
10. save identifiers from `daemonInfo`, not from QR alone

## 15. Error Handling

CLI / daemon:

| Case | Behavior |
| --- | --- |
| no control AID | `init` generates it; `init aun` asks user to run init first |
| daemon not running | CLI starts daemon |
| daemon start failed | show error and fall back to manual owner input |
| AUN not connected | QR may still be shown with warning; daemon reconnects in background |
| QR expired | task becomes expired; CLI asks user to regenerate |
| user presses `q` | CLI calls `bind.cancel` |
| bootstrap daemon finished | CLI stops bootstrap daemon |

Evol App:

| Case | Suggested Message |
| --- | --- |
| invalid JSON/type | Not an EvolClaw binding QR code |
| missing field | QR code is incomplete |
| expired QR | QR code expired; regenerate on desktop |
| AUN send failed | Network error; retry after connection recovers |
| response timeout | EvolClaw daemon did not respond |
| `INVALID_TOKEN` | Binding credential invalid; regenerate QR |
| `TASK_EXPIRED` | QR code expired; regenerate QR |
| `TASK_NOT_FOUND` | daemon restarted or task lost; regenerate QR |
| `ALREADY_BOUND` | This QR code has already been used |
| `BIND_TYPE_MISMATCH` | Binding type mismatch; regenerate QR |
| `TARGET_NOT_FOUND` | Target agent no longer exists |

## 16. Compatibility

Compatibility is determined by:

- `type === "evolclaw.bind"`
- required fields
- EvolClaw software `version` for display/troubleshooting

New App behavior:

- ignore unknown fields
- reject missing `daemonAid`
- reject missing `token`
- reject missing `agentAid` for agent binding
- treat daemon QR without `agentAid` as normal

## 17. Implementation Modules

| Module | Role |
| --- | --- |
| `src/core/bind.ts` | BindService, memory task map, token verification, owner writes |
| `src/ipc.ts` | local `bind.begin/status/cancel` IPC |
| `src/index.ts` | creates BindService and routes AUN `bind.request` |
| `src/cli/init.ts` | init flow and daemon owner binding |
| `src/cli/init-channel.ts` | `init aun` daemon/agent selection and QR flow |
| `src/cli/agent.ts` | optional agent owner binding after agent creation |

Only one new code file is introduced for the feature:

- `src/core/bind.ts`

No new socket path, no persistent bind task file, and no external task database are introduced.

## 18. Smoke Test Targets

Minimum checks:

- daemon QR has `daemonAid`, no `agentAid`, no `taskId`
- agent QR has `daemonAid`, `agentAid`, no `taskId`
- token is 16 base64url characters
- `bind.request` with token binds daemon owner
- `bind.request` with token binds agent owner
- response has no `taskId`
- daemon response has `daemonInfo.daemonAid`
- daemon response includes `baseagents`
- daemon response does not include `active_baseagent`, `model`, `effort`, or `channels`
- agent response has `daemonInfo.daemonAid` and `daemonInfo.agentAid`
- agent response includes `active_baseagent`, `model`, `effort`, and sanitized `channels`
- response does not include `ownersCount`, `ownerMode`, or raw channel credentials
- repeated used QR returns `ALREADY_BOUND`
- expired/missing token fails
- `npm run build` passes
