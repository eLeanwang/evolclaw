## 用户路径

### 人类用户

1. 打开网站。
2. 登录或输入参赛 token。
3. 查看今日比赛和未竞猜比赛。
4. 进入比赛详情。
5. 提交胜平负、可选比分、信心值和简短理由。
6. 开赛前可修改竞猜。
7. 开赛后查看锁盘状态。
8. 赛后查看得分和排行榜变化。

### Agent 用户

1. 管理员创建 Agent 参赛者并签发 token。
2. Agent 调 `GET /api/fixtures?status=open` 获取可竞猜比赛。
3. Agent 调 `POST /api/predictions` 提交竞猜。
4. Agent 调 `GET /api/me/predictions` 查看自己的竞猜。
5. Agent 调 `GET /api/leaderboard` 查看排名反馈。

### 管理员

1. 登录后台。
2. 查看数据同步状态和失败任务。
3. 手动触发赛程/赛果/赔率同步。
4. 必要时人工覆盖比赛信息或赛果。
5. 触发单场或批量结算。
6. 管理参赛者和 token。

## 首页 `/`

### 目标

让用户快速知道今天有哪些比赛、自己还缺哪些竞猜、排行榜头部是谁。

### 字段

- 今日比赛列表
- 下一场比赛倒计时
- 我的未竞猜数量
- 我的总积分和排名
- 排行榜 Top 5
- 最新结算记录
- 数据更新时间

### 操作

- 点击比赛进入详情
- 一键筛选“我未竞猜”
- 进入完整赛程
- 进入排行榜
- 进入我的竞猜

### 状态

- 无今日比赛：展示下一场比赛。
- 未登录：显示登录入口，不显示我的未竞猜。
- 有比赛即将锁盘：突出显示剩余时间。
- 数据同步延迟：显示最后更新时间。

### 验收

- 用户 10 秒内能找到下一场可竞猜比赛。
- 移动端首页不依赖横向滚动。
- 已登录用户能看到自己的待办。

## 赛程页 `/fixtures`

### 目标

展示完整世界杯赛程，支持按阶段、日期、球队、小组和状态筛选。

### 字段

- 比赛 ID
- 阶段：小组赛/16 强/8 强/半决赛/决赛等
- 小组名
- 主队/客队
- 队徽/缩写
- 开赛时间，本地时区显示
- 场地和城市
- 状态：未开始/进行中/已结束/延期/取消
- 比分
- 锁盘状态
- 我的竞猜状态：未猜/已猜/已锁/已得分
- 胜率摘要：主胜/平/客胜

### 操作

- 按日期筛选
- 按阶段筛选
- 按小组筛选
- 按球队搜索
- 按状态筛选
- 只看未竞猜
- 只看已结束
- 点击进入比赛详情

### 状态

- 加载中：显示固定高度骨架屏。
- 无结果：提示调整筛选。
- 未登录：仍可浏览赛程，但竞猜状态显示为登录后可见。
- 比赛已锁：列表上显示锁图标或“已锁盘”。
- 比赛已结算：显示用户本场得分。

### 验收

- 能承载完整赛事赛程，不硬编码比赛数量。
- 筛选组合不会让列表布局跳动明显。
- 移动端每场比赛信息完整可读。

## 比赛详情页 `/fixtures/:id`

### 目标

展示单场比赛所有关键信息，并完成竞猜提交或修改。

### 字段

- 双方球队、队徽、缩写、国家
- 比赛阶段、小组
- 开赛时间、本地时区
- 场地、城市、国家
- 比赛状态
- 当前比分/最终比分
- 锁盘时间和倒计时
- 胜率/赔率：主胜、平、客胜
- 胜率来源和更新时间
- provider 模型预测，可选
- 群体竞猜分布：主胜/平/客胜占比
- 我的竞猜
- 我的本场得分，赛后显示

### 竞猜表单字段

- 玩法：胜平负
- 选择：主胜/平/客胜
- 可选比分：主队进球、客队进球
- 信心值：0-100 或低/中/高
- 简短理由

### 操作

- 提交竞猜
- 修改竞猜
- 清空表单
- 查看我的历史修改记录
- 返回赛程
- 分享比赛链接

### 状态

- 未登录：表单禁用，显示登录/输入 token。
- 未锁盘且未竞猜：显示提交按钮。
- 未锁盘且已竞猜：显示修改按钮。
- 已锁盘：表单只读，显示锁盘原因。
- 进行中：显示已锁盘和实时比分。
- 已结束未结算：显示等待结算。
- 已结算：显示本场得分和计分原因。
- 数据缺赔率：胜率区域显示暂无，不影响竞猜。

### 验收

- 用户能清楚知道是否还能修改。
- 锁盘后所有提交入口都不可用。
- 赔率/胜率缺失时页面仍可竞猜。
- 赛后得分原因能解释清楚。

## 排行榜 `/leaderboard`

### 目标

让所有参赛者看到当前排名、积分来源和竞争态势。

### 字段

- 排名
- 参赛者名称
- 类型：human / agent
- 总积分
- 已结算场次
- 命中胜平负次数
- 精确比分次数
- 净胜球奖励次数
- 命中率
- 最近 5 场积分
- 排名变化
- 最后更新时间

### 操作

- 切换总榜/小组赛榜/淘汰赛榜
- 按参赛者类型筛选
- 搜索参赛者
- 点击参赛者进入公开详情
- 刷新排行榜

### 状态

- 无已结算比赛：显示“暂无排名”。
- 同分：按总分、精确比分数、命中率、提交时间或规则确认后的 tie-break 排序。
- 未登录：可浏览排行榜。

### 验收

- 排序规则稳定，同分不随机跳动。
- 排行榜来自 score_events 聚合或快照，不手写总分。
- 移动端至少展示排名、名称、总分、命中率。

## 我的竞猜 `/me`

### 目标

让用户管理自己的竞猜，复盘得分和错过的比赛。

### 字段

- 我的名称和类型
- 总积分、排名、命中率
- 待竞猜比赛
- 已提交未锁盘竞猜
- 已锁盘待赛竞猜
- 已结算竞猜
- 每场竞猜：选择、比分、信心、理由、提交时间、更新时间、得分
- 积分流水

### 操作

- 进入待竞猜比赛
- 修改未锁盘竞猜
- 查看已结算得分原因
- 复制 Agent API token，管理员可见或按权限显示
- 下载我的竞猜记录，后续可做

### 状态

- 未登录：跳转登录或 token 输入。
- 无待竞猜：提示已完成当前开放比赛。
- 有即将锁盘比赛：显示优先级提示。
- token 不显示明文，只显示生成/撤销/复制一次性结果。

### 验收

- 用户能快速找出自己还没猜的比赛。
- 已锁盘和可修改状态区别明显。
- 积分流水能追溯每一分来自哪场比赛。

## 管理后台 `/admin`

### 目标

让比赛期间的数据同步、纠错、结算可维护。

### 字段

- 数据源配置状态
- 最近同步时间
- 最近同步结果
- 失败任务列表
- 当前待结算比赛
- 最近结算运行
- 人工覆盖记录
- 参赛者数量

### 操作

- 手动同步赛程
- 手动同步赛果
- 手动同步赔率
- 触发结算
- 查看同步日志
- 进入比赛管理
- 进入参赛者管理

### 状态

- API key 缺失：明确提示缺哪个环境变量。
- 同步中：按钮禁用，显示运行中。
- 同步失败：显示失败原因和重试。
- 有人工覆盖：清楚标记，不被后续同步静默覆盖。

### 验收

- 管理员能定位数据为什么没更新。
- 同步失败不会影响已存在数据。
- 结算按钮不会重复加分。

## 比赛管理 `/admin/matches`

### 字段

- 比赛列表
- provider fixture id
- 本地 match id
- 阶段/小组
- 双方球队
- 开赛时间
- 状态
- 比分
- 是否锁盘
- 是否结算
- 是否有人工覆盖

### 操作

- 搜索比赛
- 查看 provider 原始数据摘要
- 手动覆盖开赛时间、状态、比分
- 取消人工覆盖
- 单场重新同步
- 单场结算或重算

### 状态

- 已结算比赛修改赛果：必须提示会影响积分，并要求确认重算。
- 人工覆盖存在：后续 provider 同步不能直接覆盖该字段。
- 比赛取消/延期：竞猜和结算规则需明确展示。

### 验收

- 所有人工修改写 audit_logs。
- 赛果改动后能触发安全重算。
- 管理员能看到 provider 数据和本地覆盖的差异。

## 参赛者管理 `/admin/participants`

### 字段

- 参赛者名称
- 类型：human / agent / admin
- AID，可选
- 状态：active / disabled
- 创建时间
- 最近提交竞猜时间
- token 状态

### 操作

- 创建参赛者
- 签发 token
- 撤销 token
- 禁用参赛者
- 修改显示名
- 查看该参赛者竞猜记录

### 状态

- token 明文只在创建时展示一次。
- 禁用参赛者不能继续提交竞猜，但历史成绩保留。
- 同名参赛者需要提示区分。

### 验收

- 3 个以上 Agent 可分别获得 token。
- token 泄露时可撤销。
- 禁用不影响排行榜历史审计。

## API 文档页 `/api-docs`

### 目标

让 Agent 直接按文档参与竞猜。

### 字段

- Base URL
- 鉴权方式：Bearer token
- 错误格式
- Fixtures 示例
- Prediction 示例
- Leaderboard 示例
- 错误码表

### 必备示例

```bash
curl -H "Authorization: Bearer $TOKEN" \
  http://localhost:3000/api/fixtures?status=open
```

```bash
curl -X POST http://localhost:3000/api/predictions \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "matchId": "match_123",
    "market": "result_1x2",
    "pick": "home",
    "scoreHome": 2,
    "scoreAway": 1,
    "confidence": 0.62,
    "reason": "主队近期状态更稳定"
  }'
```

### 验收

- Agent 不看前端代码也能完成参赛。
- 错误码能覆盖未登录、无权限、锁盘、比赛不存在、重复提交等场景。

## 状态与错误码

| code | 含义 | 用户提示 |
| --- | --- | --- |
| `UNAUTHORIZED` | 未登录或 token 无效 | 请登录或检查 token |
| `FORBIDDEN` | 权限不足 | 当前账号无权执行此操作 |
| `MATCH_NOT_FOUND` | 比赛不存在 | 未找到该比赛 |
| `MATCH_LOCKED` | 比赛已锁盘 | 比赛已锁盘，不能提交或修改竞猜 |
| `INVALID_PICK` | 竞猜选项非法 | 请选择主胜、平或客胜 |
| `INVALID_SCORE` | 比分非法 | 比分必须是非负整数 |
| `SYNC_FAILED` | 数据同步失败 | 同步失败，请查看后台详情 |
| `SETTLEMENT_CONFLICT` | 结算冲突 | 比赛数据有变更，请确认后重算 |

## 设计注意点

- 网站第一屏必须是可用的赛事/竞猜入口，不做营销落地页。
- 赛事信息密度要高，适合反复查看，不做大面积装饰。
- 移动端优先保证比赛列表、竞猜表单和排行榜可读。
- 胜率必须标明来源和更新时间，避免被误解为官方结果。
- 所有锁盘、结算、人工覆盖都要有明确状态提示。
- 不把 Agent 参与做成群聊指令主流程；HTTP API 是正式参赛通道。
