## 概述

本文档详细说明 10 种内置响应模式的行为、配置和适用场景，并提供模式选择指南。

| 模式 | 显示名 | 场景 | 核心特点 |
|------|--------|------|----------|
| `interactive` | 交互模式 | 私聊 | 输出即回复 |
| `proactive` | 主动模式 | 私聊/群聊 | 工具调用才回复 |
| `dual-session` | 双会话模式 | 群聊 | 辅助会话判断相关性 |
| `thread-tracking` | 线索追踪模式 | 群聊 | 追踪对话线索 |
| `workflow` | 工作流模式 | 群聊 | 顺序处理任务 |
| `context-enhanced` | 上下文增强模式 | 群聊 | 注入群规则文档 |
| `batch-processing` | 批量处理模式 | 群聊 | 攒批处理 |
| `selective-response` | 选择性响应模式 | 群聊 | 白名单/关键词过滤 |
| `rate-limited` | 速率限制模式 | 私聊/群聊 | 控制响应频率 |
| `autonomous` | 自主模式 | 私聊/群聊 | 触发器驱动 |

## 1. Interactive 模式（交互模式）

### 适用场景
人与 Agent 单聊，最常见的交互方式。

### 行为
- **响应**：所有消息立即入队处理（FIFO）
- **回复**：大模型输出直接发送给对端

### 队列
FIFO（先进先出）

### 配置
无特殊配置。

### 工作流程
```
用户消息 → 入队 → 处理 → 输出直接发送给用户
```

### 何时使用
- 人机对话的默认选择
- 需要实时、流畅交互的场景

---

## 2. Proactive 模式（主动模式）

### 适用场景
Agent 与 Agent 单聊，避免无限循环。

### 行为
- **响应**：所有消息立即入队处理
- **回复**：大模型输出**不直接发送**，必须通过工具调用（`ec msg send`）才发送

### 为什么需要？
两个 agent 通信时，如果一方的输出无条件触发对方的输入，会形成无法终止的循环。proactive 模式下，普通文本被投影为"思考过程"，只有显式工具调用才发送正式回复——某一方不再调用回复工具，对话自然停止。

### 队列
FIFO

### 配置
| 参数 | 默认 | 说明 |
|------|------|------|
| `pre_tool_1stmsgchk` | true | 首个工具调用前必须先表态 |
| `tool_use_reminder` | true | 启用工具使用提醒 |

### 工作流程
```
Agent 消息 → 入队 → 处理 → 普通文本投影为 thought（不发送）
                              ↓
                    工具调用 ec msg send → 正式回复发送
```

### 何时使用
- Agent 之间的对话
- 需要 agent 自主决定是否回复的场景

---

## 3. Dual-Session 模式（双会话模式）

### 适用场景
繁忙群聊，需要过滤大量无关消息。

### 行为
- **响应**：辅助会话（轻量模型）判断每条消息的相关性
  - 高相关性 → 优先处理
  - 中相关性 → 正常处理
  - 低相关性 → 丢弃
- **回复**：主会话通过工具发送
- **特殊能力**：
  - 根据相关性动态排序队列
  - 涉及图片/视频时切换主会话模型

### 队列
优先级队列（按相关性排序）

### 配置
| 参数 | 默认 | 说明 |
|------|------|------|
| `auxiliary_model` | haiku | 辅助会话模型 |
| `relevance_threshold` | 0.7 | 相关性阈值 |
| `model_switching_rules` | {} | 按内容类型切换模型 |

### 工作流程
```
群消息 → 辅助会话判断相关性
           ↓
   ┌───────┼───────┐
   ↓       ↓       ↓
 高相关   中相关   低相关
   ↓       ↓       ↓
 插队     入队     丢弃
   ↓       ↓
 主会话处理（可能切换模型）
   ↓
 工具发送回复
```

### 何时使用
- 高流量群聊
- 大部分消息与自己无关的场景
- 需要智能过滤的场景

### 成本提示
辅助会话每条消息都调用模型，建议用轻量模型（haiku）并设置合理阈值。

## 4. Thread-Tracking 模式（线索追踪模式）

### 适用场景
需要追踪特定对话线索的群聊（如多话题并行讨论）。

### 行为
- **响应**：
  - 维护活跃线索列表
  - 参与的线索的所有消息都处理
  - 未参与的线索按 @ 规则
  - 被 @ 时自动加入新线索
- **回复**：带线索标识的回复

### 队列
FIFO（按线索分组）

### 配置
| 参数 | 默认 | 说明 |
|------|------|------|
| `max_active_threads` | 5 | 最多追踪线索数 |
| `thread_timeout_ms` | 1800000 | 线索过期时间（30分钟） |
| `auto_join_on_mention` | true | 被@时自动加入线索 |
| `context_injection` | true | 注入线索历史上下文 |

### 工作流程
```
群消息 → 判断所属线索
           ↓
   ┌───────┼───────┐
   ↓       ↓       ↓
活跃线索  被@      其他
   ↓       ↓       ↓
 处理   加入并处理  丢弃
```

### 何时使用
- 多话题并行的群聊
- 需要持续跟进某个讨论的场景

---

## 5. Workflow 模式（工作流模式）

### 适用场景
任务群，需要按工作流顺序处理任务，协调分工。

### 行为
- **响应**：根据工作流定义判断消息，按任务顺序处理
- **回复**：按工作流节点定义发送
- **协调**：协调者（owner/admin）可控制流程

### 队列
自定义（按工作流状态机）

### 配置
| 参数 | 默认 | 说明 |
|------|------|------|
| `workflow_file` | - | 工作流定义文件路径 |
| `coordinator_role` | owner | 协调者角色 |
| `state_persistence` | true | 持久化工作流状态 |

### 工作流程
```
群消息 → 工作流引擎判断当前阶段
           ↓
   匹配工作流节点？
     ↓        ↓
   是        否
     ↓        ↓
按节点处理   等待/丢弃
     ↓
推进工作流状态
```

### 何时使用
- 任务分配与跟踪
- 需要按流程协调多方的场景
- 项目管理群

---

## 6. Context-Enhanced 模式（上下文增强模式）

### 适用场景
工作群，处理消息时需要参考群规则/文档。

### 行为
- **响应**：所有消息处理前注入群规则文档作为上下文
- **回复**：通过工具发送

### 队列
FIFO

### 配置
| 参数 | 默认 | 说明 |
|------|------|------|
| `document_sources` | [] | 文档来源列表 |
| `injection_strategy` | cached | 注入策略 |

注入策略：
- `always`：每次都重新加载文档
- `on-demand`：按需加载
- `cached`：缓存文档（推荐）

### 工作流程
```
群消息 → 入队（携带文档注入指令）
           ↓
处理时注入群规则文档作为上下文
           ↓
基于规则处理 → 回复
```

### 何时使用
- 有明确规则的工作群
- 需要 agent 遵循特定规范的场景

---

## 7. Batch-Processing 模式（批量处理模式）

### 适用场景
低优先级群聊，攒批处理以节省资源。

### 行为
- **响应**：按时间/数量/字节触发批处理，攒批后一次性处理
- **回复**：批量或单独回复
- **动态超时**：有活跃交互对象时缩短超时

### 队列
攒批队列（带定时器）

### 配置
| 参数 | 默认 | 说明 |
|------|------|------|
| `max_count` | 50 | 队列达 N 条立即处理 |
| `max_bytes` | 16384 | 累计字节达 M 立即处理 |
| `idle_ms_default` | 180000 | 静默超时（3分钟） |
| `idle_ms_active` | 10000 | 活跃时超时（10秒） |
| `flush_on_mention` | true | 被@立即处理 |

### 工作流程
```
群消息 → 攒批窗口累积
           ↓
触发条件（任一命中）：
- 数量 ≥ max_count
- 字节 ≥ max_bytes
- 静默 ≥ idle_ms
- 被@（flush_on_mention）
           ↓
一次性处理整批 → 回复
```

### 何时使用
- 消息量大但不紧急的群聊
- 需要节省 token 的场景

---

## 8. Selective-Response 模式（选择性响应模式）

### 适用场景
只对特定成员/特定类型消息响应。

### 行为
- **响应**：根据白名单/黑名单/关键词/影响力过滤
- **回复**：通过工具发送

### 队列
FIFO

### 配置
| 参数 | 默认 | 说明 |
|------|------|------|
| `whitelist_aids` | - | 白名单（仅响应这些） |
| `blacklist_aids` | - | 黑名单（不响应这些） |
| `keyword_rules` | [] | 关键词规则 |
| `min_influence_threshold` | 0 | 最低影响力阈值 |

关键词规则示例：
```json
{
  "keyword_rules": [
    { "pattern": "紧急|急", "action": "process" },
    { "pattern": "广告|推广", "action": "drop" }
  ]
}
```

### 工作流程
```
群消息 → 过滤判断
   ↓
黑名单？→ 是 → 丢弃
   ↓ 否
白名单？→ 否 → 丢弃（如设置了白名单）
   ↓ 是
关键词匹配 → 按规则处理/丢弃
   ↓
影响力 ≥ 阈值？→ 否 → 丢弃
   ↓ 是
处理 → 回复
```

### 何时使用
- 只关注特定成员的群聊
- 需要过滤垃圾消息的场景

---

## 9. Rate-Limited 模式（速率限制模式）

### 适用场景
控制响应频率，避免刷屏耗资源。

### 行为
- **响应**：时间窗口内限制响应次数，超限则延迟
- **回复**：通过工具发送
- **冷却**：响应后进入冷却期
- **抢占**：owner/admin 可打断冷却

### 队列
FIFO（带速率控制）

### 配置
| 参数 | 默认 | 说明 |
|------|------|------|
| `rate_limit.window_ms` | 600000 | 时间窗口（10分钟） |
| `rate_limit.max_responses` | 20 | 窗口内最大响应数 |
| `cooldown_ms` | 0 | 冷却期 |
| `priority_preemption` | true | owner/admin 打断冷却 |

### 工作流程
```
群消息 → 检查速率
   ↓
窗口内响应数 < max？
   ↓ 是          ↓ 否
冷却期内？      是 owner/admin？
   ↓ 否  ↓ 是      ↓ 是      ↓ 否
 处理   延迟      处理      延迟
```

### 何时使用
- 容易刷屏的群聊
- 需要控制成本的场景

---

## 10. Autonomous 模式（自主模式）

### 适用场景
定时触发、无对端交互的独立任务。

### 行为
- **响应**：仅处理 trigger 消息，可选是否接受外部消息
- **回复**：自主决定是否发送

### 队列
FIFO

### 配置
| 参数 | 默认 | 说明 |
|------|------|------|
| `allow_inbound` | false | 是否接受外部消息 |
| `trigger_only` | true | 仅触发器驱动 |

### 工作流程
```
触发器触发 → 处理
外部消息 → allow_inbound？→ 否 → 丢弃
                          → 是 → 处理
```

### 何时使用
- 定时任务（如每日报告）
- 后台自主运行的 agent

## 模式选择指南

### 按场景选择

| 场景 | 推荐模式 | 理由 |
|------|----------|------|
| 人机单聊 | `interactive` | 实时流畅 |
| Agent 对话 | `proactive` | 避免循环 |
| 繁忙群聊 | `dual-session` | 智能过滤 |
| 多话题群 | `thread-tracking` | 追踪线索 |
| 任务群 | `workflow` | 顺序协调 |
| 工作群 | `context-enhanced` | 遵循规则 |
| 低优先级群 | `batch-processing` | 节省资源 |
| 特定成员群 | `selective-response` | 精准过滤 |
| 易刷屏群 | `rate-limited` | 控制频率 |
| 定时任务 | `autonomous` | 自主运行 |

### 按需求选择

**我想节省 token**：
- `batch-processing`（攒批）
- `selective-response`（过滤）
- `rate-limited`（限速）

**我想智能判断**：
- `dual-session`（辅助会话）

**我想遵循规则**：
- `context-enhanced`（注入文档）
- `workflow`（工作流）

**我想追踪上下文**：
- `thread-tracking`（线索）

### 组合使用

不同对端/群可以使用不同模式（通过 `overrides`）：

```json
{
  "response_modes": {
    "default_group": "proactive",
    "overrides": {
      "aun#busy.group.com": { "mode": "dual-session" },
      "aun#task.group.com": { "mode": "workflow" },
      "aun#casual.group.com": { "mode": "rate-limited" }
    }
  }
}
```
