## 四、核心设计特点总结

### 4.1 Cache 稳定性保证

```
问题: 动态切换系统提示词 → Cache 失效

解决:
  主会话系统提示词: 固定（仅策略索引）
  策略提示词: 按需加载，注入到用户消息
  
结果: Cache 100% 稳定
```

### 4.2 辅助会话边界清晰

```
输入: AUN 消息
输出: 结构化 JSON（不是工具调用！）
禁止: 直接回复对端、写文件、调用外部 API

四大职责:
  1. 交互形态判断
  2. 行动策略选择
  3. 主会话模型选择 ⭐
  4. 消息预处理
```

### 4.3 自我进化机制

```
初始: 7 种形态 + 8 种策略（种子）
机制: 每日评估、发现问题、优化调整
支持: 关系级定制

触发条件:
  - fallback 使用频率高
  - 主会话频繁覆盖决策
  - 相似场景反复出现
```

### 4.4 双队列架构

```
辅助队列:
  批次触发: 延迟3s / 最长15s / 紧急 / 队列满
  输出: 结构化 JSON

主队列:
  优先级队列: normal / high / interrupt
  支持打断
  可被辅助会话操作
```

## 五、使用流程

### 启动系统

1. **加载 ECK Vars**
   ```yaml
   responseMode: 'dual-session'
   sessionType: 'auxiliary' | 'main'
   ```

2. **辅助会话启动**
   - 加载 `prompts/auxiliary/base.md`
   - 加载初始种子 `design/initial-seeds.md`
   - 初始化消息队列

3. **主会话启动**
   - 加载 `prompts/main/base.md`（固定，Cache）
   - 初始化消息队列

### 消息处理

1. **AUN 消息到达** → 进入辅助队列
2. **辅助会话批次处理** → 输出决策 JSON
3. **代码解析并操作主队列** → 插入/折叠/忽略
4. **主会话批次处理** → 按需加载策略 → 生成回复
5. **反馈给辅助会话** → 更新交互状态
