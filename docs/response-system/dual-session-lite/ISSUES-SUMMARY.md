## 二、P0 级问题（阻塞发布）

### ✅ P0-1: 回复发送路径不明确

**结论**：已澄清
- proactive 模式主会话通过 CLI 发送消息
- interactive 模式直接输出即回复

---

### ✅ P0-2: 单聊场景设计缺失

**结论**：已解决
- 单聊与群聊使用相同的双会话机制
- 差异：无 hold、延迟不加随机、队列满 15 条、主会话空闲触发

---

### ✅ P0-3: HOLD 消息永不清理，队列无界增长

**结论**：不是问题
- HOLD 是"暂时挂起"，不是"永久不投递"
- 队列满强制投递（群聊 50 条，单聊 15 条）
- 已处理消息不重复输入（token 不会线性增长）

---

### ✅ P0-4: 与现有群聊 mention 静默机制未明确集成关系

**结论**：已解决
- 废弃 dispatchMode 概念
- 所有消息进辅助队列，由辅助会话判断
- 旁路 mention 过滤机制

---

### ✅ P0-5: 打断机制副作用完全未交代

**结论**：不是问题
- 打断的副作用无法撤回（明确设计）
- 辅助会话决策时要谨慎打断

---

### ✅ P0-6: 打断后消息处理缺失

**结论**：已解决
- 辅助会话输出策略：打断后的正确做法
- 主会话注入打断信息：消息来源、打断原因

---

### ✅ P0-7: 主会话调用失败处理缺失

**结论**：已解决
- 重试 3 次（5秒、10秒、30秒退避）
- 消息回退到来源队列，标记错误
- 智能提取规则：上次成功可重试，上次失败跳过
- **补充降级机制**：
  - HOLD 超时投递（1 小时）
  - 辅助会话失败降级（延迟 2 分钟批量投递）

---

## 三、P1 级问题（强烈建议修复）

### ✅ P1-1: agent↔agent 回环防护缺失

**结论**：不是问题
- 自己消息回声过滤已存在
- 回复由主会话自主决定
- base agent 有足够上下文判断是否需要回复

---

### ✅ P1-2: 竞争回避在慢 agent 下失效

**结论**：已解决
- 延迟等级机制：short/medium/long
- 随机数错开判断时刻
- 不能完全消除竞争，但大幅降低概率

---

### ✅ P1-3: interrupt 在队列>50 时失效

**结论**：已解决
- 打断时提取所有消息（最多 100 条/20k 字节）
- 不受队列满限制
- 保证打断时主会话能看到完整上下文

---

### ✅ P1-4: feedback-ack 浪费一次辅助 LLM 调用

**结论**：已解决
- MainFeedback 直接插入辅助队列
- 被动触发（等待新消息到达时一起处理）
- 省去专门的 LLM 调用

---

### ✅ P1-5: 压缩机制重复设计

**结论**：不是问题
- 主会话和辅助会话复用相同压缩机制（调用 SDK /compact）
- 保持现状，未来增强作为独立设计

---

### ✅ P1-6: 并发与时序完全未设计

**结论**：不是问题
- 队列机制天然串行化
- 所有触发都通过队列，不直接触发处理
- 没有并发写入问题

---

### ✅ P1-7: 队列不持久化

**结论**：已解决
- 单会话模式已有持久化（全局 message-queue.json）
- 双会话模式需要新的持久化机制：
  - 路径：`$AGENT_DIR/relations/<channel>#<peerId>/_threads/<threadId>/_queues/`
  - 文件：`main-queue.json` 和 `auxiliary-queue.json`
  - 按话题级分离存储

**结论**：不是问题

- 不需要额外的 `delayType` 字段

**结论**：关闭
- 采用有状态辅助会话
- 主会话反馈机制依赖有状态设计
- 复用现有会话和压缩机制

## 五、关键设计更新

### 5.1 辅助会话失败降级策略

**HOLD 超时投递**：
- HOLD 超过 1 小时 → 自动投递到主队列
- 检查时机：每次辅助会话处理时检查

**辅助会话失败降级**：
```
第一次失败
↓
退避重试 3 次（5秒、10秒、30秒）
↓
重试失败
↓
标记错误状态（isInError = true）
返回降级决策（delay 2分钟）
↓
后续失败
↓
直接返回降级决策（不重试）
↓
调用成功
↓
清除错误状态（isInError = false）
```

**优势**：
- ✅ 消息可达性保证
- ✅ 批量处理降低 token 消耗
- ✅ 系统鲁棒性强
- ✅ 自动恢复机制

---

### 5.2 数据结构更新

**QueuedMessage 新增字段**：
```typescript
interface QueuedMessage {
  // ...
  holdSince?: number;  // 首次 HOLD 的时间
}
```

**AuxiliarySession 新增错误状态**：
```typescript
interface AuxiliaryErrorState {
  isInError: boolean;
  consecutiveFailures: number;
  lastSuccessTime?: number;
}
```

---

### 5.3 队列持久化

**路径**：
```
$AGENT_DIR/relations/<channel>#<peerId>/_threads/<threadId>/_queues/
├── main-queue.json
└── auxiliary-queue.json
```

**要点**：
- 按话题级分离存储
- 主队列和辅助队列分别持久化
- 懒加载机制（启动时标记需要重载，操作时检查）
