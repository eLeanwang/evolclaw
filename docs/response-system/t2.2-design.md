# T2.2 设计：物理队列与逻辑队列桥接

## 问题分析

### 当前架构

```
MessageQueue (物理队列)
  ├─ queues: Map<queueKey, QueuedMessage[]>  // 消息存储
  ├─ processNext()                            // 循环处理
  │   └─ dequeueGreedy()                     // 取下一批消息
  │       └─ queue.shift()                   // ← 直接从数组取
  └─ enqueue()                                // 入队
      └─ queues.get(queueKey).push()         // ← 直接追加到数组
```

**问题**：
- 队列顺序硬编码为 FIFO（数组的 push/shift）
- 响应模式无法自定义出队顺序

---

## 设计方案

### 架构

```
                    MessageQueue (物理队列)
                    ├─ messageStore: Map<queueKey, Map<messageId, QueuedMessage>>  // 消息存储（改为 Map）
                    ├─ logicalQueues: Map<queueKey, MessageQueueInterface>        // 逻辑队列实例
                    ├─ processNext()
                    │   └─ 1. logicalQueue.dequeue() → messageId
                    │       2. messageStore.get(messageId) → QueuedMessage
                    │       3. 处理消息
                    └─ enqueue()
                        └─ 1. messageStore.set(messageId, item)
                            2. logicalQueue.enqueue(message)
```

### 核心变化

1. **消息存储分离**：
   - 旧：`queues: Map<queueKey, QueuedMessage[]>`（顺序+存储混在一起）
   - 新：`messageStore: Map<queueKey, Map<messageId, QueuedMessage>>`（只存储）
   
2. **逻辑队列管理顺序**：
   - `logicalQueues: Map<queueKey, MessageQueueInterface>`
   - 默认 FIFO，响应模式可提供自定义队列

3. **入队流程**：
   ```typescript
   async enqueue(...) {
     const queueKey = getQueueKey(...);
     const messageId = generateMessageId(message);
     
     // 1. 存储消息本体
     if (!this.messageStore.has(queueKey)) {
       this.messageStore.set(queueKey, new Map());
     }
     this.messageStore.get(queueKey)!.set(messageId, queuedMessage);
     
     // 2. 入队到逻辑队列
     const logicalQueue = this.getOrCreateLogicalQueue(queueKey);
     await logicalQueue.enqueue({
       messageId,
       peerId: message.peerId,
       content: message.content,
       chatType: message.chatType,
       isMentioned: message.isMentioned,
       // ... 其他字段
     });
   }
   ```

4. **出队流程**：
   ```typescript
   private dequeueGreedy(queueKey: string): QueuedMessage[] {
     const logicalQueue = this.logicalQueues.get(queueKey);
     if (!logicalQueue) return [];
     
     // 1. 从逻辑队列取下一个 messageId
     const inboundMsg = await logicalQueue.dequeue();
     if (!inboundMsg) return [];
     
     // 2. 从存储取消息本体
     const messageId = inboundMsg.messageId;
     const store = this.messageStore.get(queueKey);
     const item = store?.get(messageId);
     if (!item) {
       logger.warn(`Message ${messageId} not found in store`);
       return [];
     }
     
     // 3. 移除已处理的消息
     store.delete(messageId);
     
     // 4. 贪心合并逻辑（保持现有）
     const result = [item];
     // ... 现有的 merge 逻辑
     return result;
   }
   ```

## 实施步骤

### 步骤 1：添加逻辑队列字段

在 MessageQueue 类中添加：
```typescript
private messageStore = new Map<string, Map<string, QueuedMessage>>();  // queueKey → messageId → item
private logicalQueues = new Map<string, MessageQueueInterface>();      // queueKey → queue
```

### 步骤 2：生成稳定的 messageId

```typescript
private getMessageId(message: Message): string {
  // 优先使用消息自带的 ID
  if (message.messageId) return message.messageId;
  
  // 否则生成唯一 ID（peerId + timestamp + random）
  const ts = message.timestamp || Date.now();
  const random = Math.random().toString(36).substring(2, 8);
  return `${message.peerId}_${ts}_${random}`;
}
```

### 步骤 3：修改 enqueue

```typescript
async enqueue(sessionKey: string, message: Message, projectPath: string, options?: { ... }) {
  // ... 现有的去重、拦截器逻辑 ...
  
  const queueKey = this.getQueueKey(sessionKey, projectPath, options?.selfAID);
  const messageId = this.getMessageId(message);
  
  // 存储消息本体
  if (!this.messageStore.has(queueKey)) {
    this.messageStore.set(queueKey, new Map());
  }
  
  return new Promise((resolve, reject) => {
    const queuedMessage: QueuedMessage = {
      message,
      projectPath,
      agentName: options?.agentName || DEFAULT_AGENT_NAME,
      role: options?.role,
      resolve,
      reject,
    };
    
    this.messageStore.get(queueKey)!.set(messageId, queuedMessage);
    
    // 入队到逻辑队列
    const logicalQueue = this.getOrCreateLogicalQueue(queueKey);
    logicalQueue.enqueue({
      messageId,
      peerId: message.peerId,
      content: message.content,
      chatType: message.chatType || 'private',
      isMentioned: message.isMentioned,
    });
    
    // 触发处理
    if (!this.processing.has(queueKey)) {
      this.processNext(queueKey);
    }
  });
}
```

### 步骤 4：修改 dequeueGreedy

```typescript
private dequeueGreedy(queueKey: string): QueuedMessage[] {
  const logicalQueue = this.logicalQueues.get(queueKey);
  const store = this.messageStore.get(queueKey);
  
  if (!logicalQueue || !store) return [];
  
  // 从逻辑队列取下一个
  const inboundMsg = logicalQueue.dequeueSync();  // ← 需要同步版本
  if (!inboundMsg) return [];
  
  const messageId = inboundMsg.messageId || this.getMessageId(inboundMsg as any);
  const first = store.get(messageId);
  if (!first) {
    logger.warn(`Message ${messageId} not found in store`);
    return [];
  }
  
  store.delete(messageId);
  
  // 现有的贪心合并逻辑
  const result = [first];
  // ... merge logic ...
  return result;
}
```

### 步骤 5：提供默认逻辑队列

```typescript
private getOrCreateLogicalQueue(queueKey: string): MessageQueueInterface {
  if (!this.logicalQueues.has(queueKey)) {
    // 默认 FIFO，未来由响应模式提供
    this.logicalQueues.set(queueKey, new FIFOQueue());
  }
  return this.logicalQueues.get(queueKey)!;
}
```

## 兼容性问题

### 问题 1：现有代码直接访问 `queues`

**影响范围**：
- `getQueueLength()`
- `getQueueItemsBySession()`
- `hasOtherPeerQueued()`
- `persistQueues()`

**解决方案**：保留 `queues` 字段，从 `messageStore` 同步构造

```typescript
private get queues(): Map<string, QueuedMessage[]> {
  const result = new Map<string, QueuedMessage[]>();
  for (const [queueKey, store] of this.messageStore) {
    const items = Array.from(store.values());
    if (items.length > 0) {
      result.set(queueKey, items);
    }
  }
  return result;
}
```

### 问题 2：逻辑队列的 `dequeue()` 是异步的

**冲突**：`dequeueGreedy()` 在循环中，需要同步调用

**解决方案 A**：修改 `MessageQueueInterface`，加同步版本
```typescript
interface MessageQueueInterface {
  enqueue(message: InboundMessage, priority?: number): Promise<void>;
  dequeue(): Promise<InboundMessage | undefined>;
  dequeueSync(): InboundMessage | undefined;  // ← 新增同步版本
}
```

**解决方案 B**：改造 `dequeueGreedy()` 为异步
```typescript
private async dequeueGreedy(queueKey: string): Promise<QueuedMessage[]> {
  // ...
  const inboundMsg = await logicalQueue.dequeue();
  // ...
}
```

**推荐**：方案 B（改造为异步），因为 processNext 已经是异步的

## 响应模式集成点

### 响应模式如何提供队列？

```typescript
class ProactiveMode implements ResponseMode {
  getQueue(): MessageQueueInterface {
    return new PriorityQueue();  // 高优先级消息先处理
  }
}
```

### MessageQueue 如何获取响应模式的队列？

**时机**：`enqueue()` 时

```typescript
async enqueue(...) {
  const queueKey = this.getQueueKey(...);
  
  // 查询当前会话的响应模式
  const mode = this.responseModeResolver?.resolve(sessionKey);
  const logicalQueue = mode ? mode.getQueue() : new FIFOQueue();
  
  this.logicalQueues.set(queueKey, logicalQueue);
  // ...
}
```
