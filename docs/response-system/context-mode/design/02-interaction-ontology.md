## 一、交互的定义

### 1.1 什么是交互？

```
交互 (Interaction) 是群聊中的最小意义单元

定义：
  一个交互是一段具有统一主题或目标的对话流，
  由一组参与者产生的一系列相关消息组成。
```

### 1.2 交互的基本特征

```
1. 有明确的起点
   - 首条消息标志交互开始
   - 通常是新话题、新问题、新任务

2. 有（潜在的）终点
   - 目标达成
   - 超时无人响应
   - 话题切换

3. 有参与者集合
   - 至少一个发起者
   - 可能有多个响应者
   - 参与者可能动态变化

4. 有主题或目标
   - 求助、讨论、协作、社交等
   - 目标可能明确或隐含

5. 有消息序列
   - 有序的消息列表
   - 消息间有关联性
```

### 1.3 交互的生命周期

```
[创建] 起点消息发出
  ↓
[活跃] 持续接收相关消息
  ↓
  参与者增减
  状态属性变化
  可能演进到不同形态
  ↓
[终止]
  ├─ 完成: 目标达成
  ├─ 放弃: 超时无响应
  └─ 中断: 话题切换
```

## 二、核心分类维度

交互的**核心维度**定义了交互的**本质特征**，相对稳定，值是**互斥**的。

### 维度 1: 参与者结构

**定义**: 交互中参与者的组织方式

**可选值**（互斥）:

```
1. 单人→群 (1→N)
   定义: 一个人向群发起，等待响应
   特征: 
     - 发起者明确
     - 可能无人响应（冷启动）
     - 响应者可能是一人或多人
   示例: 求助、提问、分享

2. 双人对话 (1↔1)
   定义: 两个人在群内的对话
   特征:
     - 其他人可能围观但不参与
     - 相对私密的交流
   示例: 知识传授、深入讨论

3. 多人讨论 (N↔N, 平等)
   定义: 多人平等参与的讨论
   特征:
     - 无明确主导者
     - 观点交流、自由发言
   示例: 技术讨论、头脑风暴

4. 多人协作 (N↔N, 分工)
   定义: 多人协作完成任务
   特征:
     - 有分工
     - 有协调
     - 目标明确
   示例: 问题排查、跨团队协调

5. 主导→群 (Leader→N)
   定义: Owner/Admin 主导的交互
   特征:
     - 权威性
     - 单向或主导式沟通
   示例: 任务分配、会议主持、规则设定

6. 系统→群 (System→N)
   定义: 系统/Bot 发起的交互
   特征:
     - 自动化
     - 格式化
     - 周期性或事件触发
   示例: 通知、自动化消息、CI/CD 反馈
```

**演进规则**:
```
单人→群 → 多人讨论  (其他人加入)
双人对话 → 多人讨论  (更多人加入)
多人讨论 → 多人协作  (开始分工)
```

---

### 维度 2: 交互意图

**定义**: 交互想要达成的目标

**可选值**（互斥）:

```
1. 信息获取
   定义: 获取知识、解决问题、寻求帮助
   特征:
     - 有明确的问题
     - 期待答案或方案
   示例: 求助、提问、求证

2. 信息分享
   定义: 传递信息、通知、汇报
   特征:
     - 单向传递为主
     - 可能不期待回复
   示例: 通知、汇报、经验分享

3. 协作执行
   定义: 共同完成任务或工作
   特征:
     - 有明确任务
     - 需要配合
     - 有成果产出
   示例: 任务分配、问题排查、工作流执行

4. 讨论决策
   定义: 讨论问题、达成共识、做出决定
   特征:
     - 多方观点
     - 可能有分歧
     - 最终需要结论
   示例: 技术讨论、方案评审、投票

5. 社交互动
   定义: 情感交流、关系维护
   特征:
     - 无明确目标
     - 轻松随意
   示例: 闲聊、问候、感谢

6. 教学传授
   定义: 传授知识、指导新人
   特征:
     - 有经验差距
     - 单向传递为主
     - 逐步深入
   示例: 知识传授、经验分享、引导澄清
```

**演进规则**:
```
信息获取 → 讨论决策  (从提问到讨论)
讨论决策 → 协作执行  (讨论完开始执行)
社交互动 → 信息分享  (从闲聊到正题)
```

---

### 维度 3: 时间模式

**定义**: 交互如何在时间上展开

**可选值**（互斥）:

```
1. 实时同步
   定义: 即时对话，参与者同时在线
   特征:
     - 消息间隔短（< 1 分钟）
     - 快速往复
   示例: 大部分群聊对话

2. 异步串行
   定义: 跨时间回复，参与者不同时在线
   特征:
     - 消息间隔长（> 1 小时）
     - 可能跨越多天
   示例: 跨时区协作、延迟回复

3. 一次性
   定义: 单次交互，不期待后续
   特征:
     - 发完即结束
     - 无持续性
   示例: 通知、分享、感谢

4. 周期性
   定义: 定期重复的交互
   特征:
     - 固定周期
     - 内容相似
   示例: 日报、周会、定期汇报

5. 持续跟踪
   定义: 长期演进的交互
   特征:
     - 跨越较长时间
     - 多个阶段
     - 持续更新
   示例: 项目跟踪、长期任务
```

**演进规则**:
```
一次性 → 持续跟踪  (临时问题变成长期跟进)
实时同步 → 异步串行  (对话中断后恢复)
```

---

### 维度 4: 结构化程度

**定义**: 交互是否有预定的流程或模式

**可选值**（互斥）:

```
1. 自由对话
   定义: 无预定流程，自由展开
   特征:
     - 不可预测
     - 无固定模式
     - 灵活多变
   示例: 大部分闲聊和讨论

2. 半结构化
   定义: 有隐含的模式但不严格
   特征:
     - 有大致流程
     - 可以偏离
     - 有一定规律
   示例: 问题排查、头脑风暴

3. 结构化
   定义: 有明确的流程或议程
   特征:
     - 流程明确
     - 步骤清晰
     - 可预测
   示例: 工作流、会议、审批
```

**演进规则**:
```
自由对话 → 半结构化  (逐渐形成模式)
半结构化 → 结构化  (明确流程)
```

---

### 维度 5: 上下文依赖性

**定义**: 交互与历史消息的关系

**可选值**（互斥）:

```
1. 独立
   定义: 不依赖历史，新起点
   特征:
     - 可以独立理解
     - 无需回溯
   示例: 新话题、新问题

2. 弱依赖
   定义: 有上下文更好，但可独立理解
   特征:
     - 带上下文更完整
     - 不带也能理解大意
   示例: 延续讨论但有新观点

3. 强依赖
   定义: 必须有上下文才能理解
   特征:
     - 省略了主语或背景
     - 使用代词（"这个"、"那个"）
   示例: 多轮对话、深入讨论

4. 引用依赖
   定义: 明确引用特定历史消息
   特征:
     - 使用引用功能
     - 针对特定消息
   示例: 引用回复、延迟回应
```

**演进规则**:
```
独立 → 弱依赖  (开始有延续)
弱依赖 → 强依赖  (多轮深入)
```

## 三、状态属性

交互的**状态属性**描述交互的**当前状态**，容易变化，可以**同时有多个值**。

### 3.1 动态属性（易变）

#### 属性 1: 紧急程度

**可选值**: 低、正常、高、紧急

**定义**: 交互的时效性和优先级

**动态变化**:
```
正常 → 高 → 紧急  (问题升级)
紧急 → 正常  (问题缓解)
```

**影响**: 响应优先级、是否打断

---

#### 属性 2: 情绪基调

**可选值**: 中性、积极、消极、紧张、冲突

**定义**: 交互的情感氛围

**动态变化**:
```
中性 → 消极 → 冲突  (争论升级)
冲突 → 消极 → 中性  (矛盾缓和)
中性 → 积极  (达成共识、庆祝)
```

**多值**: 可以同时是"紧张+消极"

**影响**: 是否需要调解、语气选择

---

#### 属性 3: 信息完整性

**可选值**: 完整、不完整-分段、不完整-多模态、模糊、过载

**定义**: 信息的充分程度

**动态变化**:
```
不完整 → 完整  (补充信息)
模糊 → 完整  (澄清后)
```

**影响**: 是否等待、是否引导

---

#### 属性 4: 参与活跃度

**可选值**: 冷启动、低活跃、正常活跃、高活跃、过度活跃

**定义**: 参与者的活跃程度

**动态变化**:
```
冷启动 → 低活跃 → 正常活跃 → 高活跃
高活跃 → 正常活跃  (冷却)
```

**影响**: AI 介入时机

---

#### 属性 5: 共识程度（仅讨论类）

**可选值**: 未讨论、分歧大、分歧中等、分歧小、已达成共识

**定义**: 讨论类交互的一致性

**动态变化**:
```
未讨论 → 分歧大 → 分歧中等 → 分歧小 → 已达成共识
```

**影响**: 是否需要调解或总结

---

#### 属性 6: 进展阶段（仅协作类）

**可选值**: 启动、规划、执行中、遇阻、接近完成、已完成

**定义**: 协作类交互的进度

**动态变化**:
```
启动 → 规划 → 执行中 → 接近完成 → 已完成
       ↓
      遇阻 → 执行中  (解决阻塞后)
```

**影响**: 跟踪和提醒策略

---

### 3.2 上下文属性（相对稳定）

#### 属性 7: 话题专业性

**可选值**: 技术、业务、管理、通用

**定义**: 话题的专业领域

**影响**: AI 是否有能力参与

---

#### 属性 8: 发起者权限

**可选值**: 普通成员、Owner/Admin、系统/Bot

**定义**: 发起者的角色

**影响**: 优先级、权限判断

---

#### 属性 9: AI 相关性

**可选值**: 与 AI 无关、弱相关、强相关、必须 AI

**定义**: 交互与 AI 的关联程度

**动态变化**:
```
无关 → 弱相关 → 强相关  (话题转向 AI 能力范围)
```

**影响**: 参与意愿判断

---

#### 属性 10: 外部依赖

**可选值**: 无依赖、依赖外部资源、依赖外部人员、依赖外部系统

**定义**: 是否依赖群外资源

**影响**: 能否立即解决、是否需要协调

---

## 四、完整的交互模型

```typescript
interface Interaction {
  // 唯一标识
  interactionId: string;
  
  // ========================================
  // 核心分类维度（相对稳定，互斥）
  // ========================================
  dimensions: {
    participantStructure: 
      | '单人→群'
      | '双人对话'
      | '多人讨论'
      | '多人协作'
      | '主导→群'
      | '系统→群';
    
    intent:
      | '信息获取'
      | '信息分享'
      | '协作执行'
      | '讨论决策'
      | '社交互动'
      | '教学传授';
    
    timePattern:
      | '实时同步'
      | '异步串行'
      | '一次性'
      | '周期性'
      | '持续跟踪';
    
    structureLevel:
      | '自由对话'
      | '半结构化'
      | '结构化';
    
    contextDependency:
      | '独立'
      | '弱依赖'
      | '强依赖'
      | '引用依赖';
  };
  
  // ========================================
  // 状态属性（易变，可多值）
  // ========================================
  attributes: {
    // 动态属性
    urgency: '低' | '正常' | '高' | '紧急';
    emotionalTone: Array<'中性' | '积极' | '消极' | '紧张' | '冲突'>;
    informationCompleteness: '完整' | '不完整-分段' | '不完整-多模态' | '模糊' | '过载';
    participationActivity: '冷启动' | '低活跃' | '正常活跃' | '高活跃' | '过度活跃';
    
    // 条件属性
    consensusLevel?: '未讨论' | '分歧大' | '分歧中等' | '分歧小' | '已达成共识';
    progressStage?: '启动' | '规划' | '执行中' | '遇阻' | '接近完成' | '已完成';
    
    // 上下文属性
    topicProfessionalism: '技术' | '业务' | '管理' | '通用';
    initiatorPermission: '普通成员' | 'Owner/Admin' | '系统/Bot';
    aiRelevance: '与 AI 无关' | '弱相关' | '强相关' | '必须 AI';
    externalDependency: '无依赖' | '依赖外部资源' | '依赖外部人员' | '依赖外部系统';
  };
  
  // ========================================
  // 元数据
  // ========================================
  metadata: {
    startMessageId: string;
    endMessageId?: string;
    status: 'active' | 'completed' | 'abandoned';
    participants: string[];
    messages: string[];
    topic?: string;
    summary?: string;
    createdAt: number;
    updatedAt: number;
  };
}
```

## 五、如何使用这套本体

### 5.1 辅助会话的任务

```
任务 1: 理解新消息所属的交互

步骤：
  1. 检查是否属于现有活跃交互
     - 话题延续？
     - 回复某人？
     - 时间接近？
  
  2. 如果不属于，创建新交互
     - 分配 interactionId
     - 标记起点消息
  
  3. 评估交互的维度和属性
     - 5 个维度各选一个值
     - 10 个属性逐一评估

任务 2: 追踪交互演进

步骤：
  1. 每收到新消息，重新评估属性
  2. 检测维度是否演进（形态变化）
  3. 更新交互状态
```

### 5.2 判断示例

#### 示例 1: 直接求助

```
消息: "@AI 这个报错怎么解决？"

维度评估:
  participantStructure: 单人→群
  intent: 信息获取
  timePattern: 实时同步
  structureLevel: 自由对话
  contextDependency: 独立

属性评估:
  urgency: 正常
  emotionalTone: [中性]
  informationCompleteness: 完整
  participationActivity: 冷启动
  topicProfessionalism: 技术
  initiatorPermission: 普通成员
  aiRelevance: 必须 AI
  externalDependency: 无依赖
```

#### 示例 2: 技术讨论演变为争论

```
T1 (讨论开始):
  维度: 多人讨论 / 讨论决策 / 实时同步 / 自由对话 / 弱依赖
  属性:
    urgency: 正常
    emotionalTone: [中性]
    consensusLevel: 未讨论

T2 (出现分歧):
  维度: (不变)
  属性:
    urgency: 正常
    emotionalTone: [冲突]  ← 变化
    consensusLevel: 分歧大  ← 变化

形态演进: 技术讨论 → 技术争论（因属性变化）
```

## 六、与常见模式的关系

### 6.1 常见模式是维度+属性的组合

```
常见模式库中的 35 种形态
  =
特定的维度+属性组合

例如：
  A1 (直接求助) = 
    单人→群 + 信息获取 + 实时同步 + 自由对话 + 独立
    + 正常紧急 + 中性情绪 + 完整信息 + 必须 AI

  B2 (技术争论) = 
    多人讨论 + 讨论决策 + 实时同步 + 自由对话 + 弱依赖
    + 正常紧急 + 冲突情绪 + 完整信息 + 分歧大
```

### 6.2 辅助会话可以参考但不强制

```
辅助会话工作流:

1. 评估维度和属性
   ↓
2. 查询常见模式库
   if 完全匹配某个模式:
     快速采用该模式的策略建议
   else:
     基于维度和属性推导策略
   ↓
3. 输出判断
```

**关键**: 模式库是"参考"而非"规则"
