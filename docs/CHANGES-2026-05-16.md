## 主题 1：Session 存储后端从 SQLite 改为文件系统

**动机**：原来使用 `~/.evolclaw/data/sessions.db`（SQLite），引入了 `node:sqlite` 模块依赖、并发锁问题、以及 schema 迁移负担。改为按 chat 目录组织的 JSON/JSONL 文件，更易调试，也便于多进程/多机器场景演进。

### 新增模块

- **`src/core/session/session-fs-store.ts`**（~250 行）
  底层文件存储原语：
  - `chatDirPath()` — 计算 chat 目录路径
    - AUN：`{sessionsDir}/aun/<encode(selfId)>/<encode(channelId)>/`
    - 其它：`{sessionsDir}/<channelType>/<encode(channelId)>/`
  - `encodeSegment` / `decodeSegment` — 把 Windows 非法字符（`< > : " / \ | ? *` 等）按 `%XX` 编码，可逆
  - `atomicWriteJson()` — `tmp + fsync + rename` 的原子写
  - `appendJsonl()` — JSONL 追加（含 fsync）
  - `readLastJsonlLine()` / `readAllJsonlLines()` — JSONL 读取
  - `scanChatDirs()` — 遍历整个 sessions 目录
  - `scanMetaFiles()` — 列出某 chat 下所有 `meta_YYYYMMDD_TS.jsonl`
  - `ensureChatDir()` — 创建 `_threads`、`_trash` 子目录
  - `readThreadIndex()` / `writeThreadIndex()` — 话题会话索引
  - `SessionFile` 类型：磁盘上的 session 数据形态
  - `HealthRecord` 类型：健康记录形态

- **`src/core/session/session-mapper.ts`**（~80 行）
  `Session` ↔ `SessionFile` 的双向映射，剥离了 SessionManager 内部的字段铺设逻辑。

- **`src/core/session/message-log.ts`**（~140 行）
  消息收发流水（每个 chat 一份 `messages.jsonl`），用来给后续的"会话回看 / 审计 / 训练数据导出"提供原始数据：
  - `MessageLogEntry` 字段：ts/time/dir/from/to/chatType/groupId/msgId/msgType/content/replyTo/agent/model/permMode/cmdParsed/durationMs
  - `appendMessageLog()` — 入向去重（最近 200 个 msgId 滑动窗口）
  - `buildInboundEntry()` / `buildOutboundEntry()` — 入/出向条目构造器
  - 自动识别 `/` 开头的命令行（`msgType=command`、`cmdParsed=/xxx`）

### 重写的模块

- **`src/core/session/session-manager.ts`**（-833 / +627 行，几乎重写）
  - 构造器签名变更：`new SessionManager(dbPath, ...)` → `new SessionManager(sessionsDir, ...)`
  - 所有 `db.prepare(...).run()` / `.get()` / `.all()` 全部替换为 `readJsonFile` / `appendJsonl` / `scanChatDirs` 等文件系统操作
  - 私聊 chat 目录定位策略：
    - 优先按 `(channelType, selfId, channelId)` 精确解析（caller 传 `channelType`/`selfId` 时直接命中）
    - 未提供 channelType 时回落到扫描 + 实例名/类型匹配
  - 话题会话仍走 `_threads/thread-index.json` 加 `_threads/<tid>/active.json`
  - 健康状态从 `health` 表迁到每个 chat 目录的 `health.jsonl`
  - `getOrCreateSession()` 多了 `selfId`、`channelType` 两个参数，用于 AUN 多 AID 场景下精准命中
  - 删除 `migrateChannelToInstanceName()`（启动迁移）—— 老 SQLite 时代用的，新文件系统不需要

## 主题 2：单进程实例保护（instance registry）

**动机**：之前依赖单一 `evolclaw.pid` 文件 + 进程扫描去判定"是否已有实例运行"。现实中容易出现：PID 文件被强杀残留、并发 `evolclaw start`、restart-monitor 与 main 重叠等，导致两个 main 同时跑。

新模型：每个进程在 `{HOME}/data/instance/` 目录下放一份带 PID 的 record 文件作为登记簿，凭 (startedAt, pid) 字典序选赢家。

### 新增模块

- **`src/utils/instance-registry.ts`**（~360 行）
  - 文件命名：`main-<pid>.json` / `restart-monitor-<pid>.json` / `aid-<pid>.jsonl`
  - `writeMain(launchedBy)` — 注册自己（launchedBy 来自 `EVOLCLAW_LAUNCHED_BY` 环境变量：`start` / `restart-cli` / `restart-network` / `self-heal` / `restart-monitor`）
  - `isMainWinner()` / `isRestartMonitorWinner()` — post-write 自检：写完 record 立刻扫一次，按 (startedAt, pid) 选赢家；输者退出
  - `scanInstances()` — 扫描整个 instance/ 目录，对每个 record 通过 `(pid, startedAt)` 校验存活
  - `cleanupInstances()` — 杀掉非己 PID 的活实例并清残留文件
  - `removeMain()` / `removeRestartMonitor()` / `removeAll()` — 正常关闭路径
  - `appendAidEvent()` / `readAidLastActivity()` — AID 事件流水（`connected` / `disconnected` / `message_in` / `message_out`），供 `evolclaw status` 表格读取
  - 损坏的 JSON 文件 `scanInstances` 时自动删除

- **`src/utils/process-introspect.ts`**（~150 行）
  跨平台进程启动时间获取，用于 PID 重用判定：
  - Linux：解析 `/proc/<pid>/stat` 第 22 字段 + `/proc/uptime`
  - macOS：`ps -p <pid> -o lstart=`
  - Windows：优先 PowerShell `Get-CimInstance Win32_Process`，降级 `wmic`
  - `parseCimDate()` 解析 `yyyyMMddHHmmss.ffffff±TZZZ` 格式
  - `START_TIME_TOLERANCE_MS = 2000` 容差（覆盖 macOS 秒级精度）
  - `startTimeMatches(recorded, actual)` — `null` 时保守返回 false

### 修改

- **`src/index.ts`**
  - 启动序：pre-check（发现别人活就直接退出）→ writeMain（登记） → post-write 自检（输了让位）
  - shutdown / `process.on('exit')` 兜底调用 `removeAll()`
- **`src/cli.ts`**
  - `cmdStart()` / `cmdStop()` / `cmdRestart()` / `cmdStatus()` / `cmdDiagnose()` / `cmdRestartMonitor()` 全部改用 `scanInstances()` 而不是单一 PID 文件
  - `restartMonitor` 同样有 pre-check + post-write 自检
  - 多 main 场景的处理：`stop`/`restart` 并行 SIGTERM 所有活 main，`status` 检测到 >1 时打 ⚠ 提示
  - 移除 `getProcessEnv()`（基于 `/proc/<pid>/environ` 的 EVOLCLAW_HOME 探测，不再需要） → `src/utils/cross-platform.ts` 删除该函数

## 主题 3：AUN channel 重连与可靠性大改造

**动机**：原 `AUNChannel` 重连机制是 TS 层有限指数退避（4 次后放弃）。在生产里被 server 反复踢、SDK 反复重连刷屏、TS 层放弃后无人接管等问题暴露后，整体重写。

`src/channels/aun.ts` (+769 / 部分删除)，核心要点：

### 1. 重连策略重写

- SDK 层：`auto_reconnect: true, max_attempts: 0`（无限）、`initial_delay=1s`、`max_delay=300s`，与 Go/Python SDK 行为对齐
- TS 层只在 SDK 够不到的两类场景下接管：
  1. **Flap**：连续短命 connected（lifetime < 30s 累计 ≥3 次）→ TS 层强制 close + 5min 延迟
  2. **被踢类 terminal_failed**（reason 含 `kicked` 或 close code 4001/4003/4008/4009/4010/4011）→ 5min 延迟
- 其它 terminal_failed → 1min 延迟兜底
- 新机制：
  - `reconnectGeneration` 单调递增 token，防止旧 initClient 回调污染新连接
  - `initInProgress` flag 防 sendMessage 触发与 timer 触发并发 init
  - `RECONNECT_LOG_INTERVAL = 60s` + `RECONNECT_LOG_STEP = 100` 节流日志
- 删掉了：`SDK_RECONNECT_GIVEUP=50`、`RECONNECT_DELAYS=[60,120,300,600]`、有限重连次数提示等老逻辑

### 2. 同 AID 互踢自描述（`extra_info`）

- `buildConnectExtraInfo()` 在 connect 时上报：`app/version/pid/started_at/hostname/platform/node_version/evolclaw_home/launched_by/aid/agent_name/channel_name`
- SDK 新事件 `gateway.disconnect`：被踢方从 `detail.self_extra_info` 看到自己当时的 extra_info、从 `detail.new_extra_info` 看到挤掉自己的对手身份
- `handleGatewayDisconnect()` 把双方信息打到 `logger.warn`，便于通过 `evolclaw watch` 一眼看到"谁踢的我"

### 3. AID 状态聚合

- 新类型 `AidConnectionState`（在 `src/types.ts`）：
  ```ts
  status: 'connected' | 'reconnecting' | 'aid_blocked' | 'kicked' | 'failed' | 'disabled'
  reconnectCount, flapCount, lastAttemptAt, lastConnectedAt, lastError, blockedBy, agentName, channelName
  ```
- `AUNChannel.getAidState()` 返回快照，供 `evolclaw status` 通过 IPC 聚合
- 内部所有连接状态变更都更新 `aidState`（initClient 失败、kicked、flap 接管、connected 等）

### 4. Outbox（write-ahead 发送队列）

新模块 **`src/utils/outbox.ts`**（~160 行）：
- 每个 AID 一个 `{HOME}/data/outbox/<aid>.jsonl`
- `enqueue(aid, opts)` — 发送前先入队，未发出时进程崩溃也不丢
- `remove(aid, id)` — 发送成功后移除
- `drain(aid, sender)` — 重连成功时一次性补发
- `MAX_ENTRIES_PER_AID = 20`（超过丢最老）
- `DEFAULT_TTL = 5 min`（过期丢弃）

`AUNChannel`：
- `sendMessage` / `sendFile` 改为 enqueue → 立即尝试 deliver → 成功 remove；失败/未连接时留在 outbox
- 新增 `deliverTextEntry()` / `deliverFileEntry()` 内部投递函数
- `connect()` 启动 30s 周期的 `outboxTimer`，`drainOutbox()` 在 connected 状态变化时触发
- `disconnect()` / `stopOutboxTimer()` 配套清理

### 5. Echo 调试机制

为了排查 "agent 收到了消息但 AUN 没回声" 类问题，新增 echo trace：
- 收到的消息第一行包含 `echo`（不区分大小写）：
  - **≤10 字符**：`handleEcho()` 直接回声，不走 agent，附带 `[EvolClaw.receive]` / `[EvolClaw.reply]` trace 行
  - **>10 字符**：在文本末尾追加 `[EvolClaw.receive]` 行，存 `pendingEchoMessages`，正常交给 agent；agent 第一次回复前由 `flushPendingEcho()` 把追加 trace 的原文发出去（含 agent duration）
- 私聊和群聊都支持；群聊时跳过 mention 过滤
- `isEchoSending` flag 防止 echo 自身触发 flushPendingEcho 递归

### 6. ChannelId 简化

- 私聊 `channelId` 一律用对端 AID（之前可能是 `aid:device_id:slot_id` 三段式）
- 多处调用点（`sendMessage` / `sendFile` / `sendStatusEvent` / `sendCustomPayload`）的"提取 colon prefix"逻辑全部删除
- `payload.chat_id` 注入也删了——device_id 维度由 SDK 内部消化，evolclaw 不再下沉

### 7. 入站 dispatch 携带更多字段

- `dispatchMessage()` 给 handler 多传 `channelType: 'aun'`、`selfId`（本地 AID）、`groupId`（群聊）
- `appendAidEvent` 在 connect/disconnect/message_in/message_out 各打点

SessionMetadata {

## 影响面与兼容性

- **不自动迁移 SQLite → 文件系统**：旧 `sessions.db` 留在原地，启动时打 warn。用户需要新会话即可，老会话历史在 SQLite 文件里保留作存档。
- **彻底移除旧 `evolclaw.pid` 文件**：`paths.pid` 字段、`isRunning(pidFile)` / `stopAndWait(pidFile)` 函数、所有 `cmdStop`/`cmdRestart`/`cmdStatus`/`cmdRestartMonitor`/`init` 里基于旧 PID 文件的兜底分支全部删除。从这次升级开始单实例判定只走 instance registry 的 `main-<pid>.json`。残留的旧 PID 文件不会被读，需要手动 `rm logs/evolclaw.pid` 清理（不影响行为，仅清洁度）。
- **多 main 检测**：升级后第一次 `evolclaw status` 可能提示"⚠ 检测到 N 个 main 实例"，这是 instance registry 在揭示历史问题，按提示 `evolclaw restart` 即可统一。
- **aun.ts ChannelId 简化**：如果配置/数据库里有 `aid:device:slot` 三段式 channelId 残留，新代码当成对端 AID 整体，可能 routing 不到原会话。SQLite → 文件系统已经天然换库，不算新增风险。
