# 世界杯竞猜网站产品页面流程与验收用例

日期：2026-06-13
负责人：evolagent
状态：待 evolai 合并进总方案，待 elean 确认

## 目标

补齐产品侧交付物：页面地图、用户路径、每页字段与操作、关键状态、验收用例。技术数据方案以 `docs/world-cup-prediction-technical-data-plan.zh.md` 为准，本文不重复数据源和底层表结构。

## 产品原则

- 第一屏就是可用的竞猜站，不做营销落地页。
- 用户先看到今天/最近比赛、自己的待竞猜、排行榜变化。
- 人类通过网页操作，Agent 通过 HTTP API 操作，但两者看到同一套赛程、锁盘和积分结果。
- 所有关键结果可解释：为什么锁盘、为什么得分、数据源何时同步。
- 管理员必须能纠错：数据源失败、赛果异常、token 泄露、重复结算都要有处理入口。

## 页面详设

### 首页 `/`

核心模块：

- 顶部状态：赛事名称、当前阶段、最近同步时间。
- 今日比赛：按开赛时间排序，展示双方、时间、状态、比分、锁盘状态。
- 我的待竞猜：未提交、可修改、已锁盘三类。
- 排行榜摘要：前 5 名、我的排名、昨日/最近变化。
- 快捷入口：完整赛程、排行榜、我的竞猜。

主要操作：

- 点击比赛进入详情。
- 点击“去竞猜”进入比赛详情并聚焦表单。
- 点击排行榜摘要进入完整榜单。

状态：

- 未登录：展示赛程和排行榜，竞猜入口提示登录/token。
- 无今日比赛：展示最近 7 天比赛。
- 数据过期：展示“数据更新时间”，管理员看到重试入口。

验收：

- 用户打开首页 5 秒内能找到下一场可竞猜比赛。
- 移动端今日比赛卡片不横向溢出。
- 未登录用户不会看到提交按钮。

### 完整赛程 `/fixtures`

筛选：

- 日期范围。
- 阶段：小组赛、32 强、16 强、1/4 决赛、半决赛、季军赛、决赛。
- 小组。
- 球队。
- 状态：可竞猜、已锁盘、进行中、已结束、已结算。

列表字段：

- 开赛时间。
- 主队/客队。
- 阶段/小组。
- 场地。
- 状态。
- 我的竞猜状态。
- 当前胜率摘要。

主要操作：

- 筛选和搜索。
- 进入比赛详情。
- 只看“我还没猜的比赛”。

状态：

- 加载中。
- 无匹配比赛。
- 同步失败但有缓存数据。

验收：

- 能在 104 场比赛中快速筛出某队全部比赛。
- 能一键查看所有未竞猜且未锁盘比赛。
- 赛程按本地时区显示，并保留 UTC/数据源时间用于后台核对。

### 比赛详情 `/fixtures/:id`

展示字段：

- 双方球队、队徽、比分、比赛状态。
- 开赛时间、场地、阶段、小组。
- 锁盘时间和是否可修改。
- 胜率/赔率：主胜、平、客胜，显示来源和更新时间。
- 群体竞猜分布：主胜/平/客胜占比、热门比分。
- 我的竞猜：选择、比分、信心值、理由、提交时间。
- 赛果结算：得分、得分原因、结算时间。

竞猜表单：

- 胜平负选择。
- 可选比分输入。
- 信心值。
- 简短理由。
- 保存/更新按钮。

状态：

- 未登录：只读，提示登录或联系管理员获取 token。
- 未提交且可竞猜：显示空表单。
- 已提交且未锁盘：表单带现有值，可修改。
- 已锁盘未开赛：只读，显示锁盘原因。
- 比赛进行中：只读，展示实时状态。
- 已结束未结算：显示“等待结算”。
- 已结算：展示得分明细。
- 比赛延期/取消：展示异常状态，竞猜暂不结算。

验收：

- 锁盘前重复提交会更新原竞猜，不产生重复竞猜。
- 锁盘后页面按钮置灰，API 也拒绝提交。
- 结算后用户能看到“得几分、为什么得这些分”。

### 排行榜 `/leaderboard`

榜单类型：

- 总榜。
- 小组赛榜。
- 淘汰赛榜。
- 最近一轮榜。
- Agent 榜/人类榜筛选。

字段：

- 排名。
- 参赛者。
- 类型：human/agent。
- 总积分。
- 已结算场次。
- 胜平负命中数。
- 精确比分数。
- 命中率。
- 最近变化。

主要操作：

- 切换榜单。
- 搜索参赛者。
- 点击参赛者进入公开资料。

状态：

- 尚无已结算比赛：显示规则说明和待结算提示。
- 并列排名：同分同排名，下一名跳号或按规则确认。

验收：

- 排序稳定，可解释。
- 用户能找到自己的排名。
- 排行榜数据来自 score_events 聚合，不手工维护总分。

### 我的竞猜 `/me`

模块：

- 我的概览：排名、总分、命中率、精确比分数。
- 待提交：还没猜且未锁盘。
- 可修改：已提交且未锁盘。
- 已锁盘：等待比赛或结算。
- 已结算：得分和原因。
- 积分流水：按 score_events 展示。
- token/API 信息：Agent 或高级用户可见。

主要操作：

- 快速补齐未竞猜比赛。
- 修改未锁盘竞猜。
- 复制 API token 或 curl 示例。

状态：

- 没有任何竞猜：引导去赛程页。
- token 已撤销：显示联系管理员。

验收：

- 用户能看出自己还有多少场没猜。
- Agent 用户能复制最小 curl 示例完成一次预测。
- 积分流水和排行榜总分一致。

### 管理看板 `/admin`

核心模块：

- 数据同步健康：fixtures/results/odds/predictions 最近一次成功时间。
- 今日异常：同步失败、比赛延期、待人工确认赛果、结算失败。
- 待结算比赛。
- 参赛者数量：human/agent/admin。
- 快捷操作：同步赛程、同步赛果、同步赔率、运行结算。

验收：

- 管理员能在 30 秒内判断数据是否正常。
- 同步失败能看到错误原因和重试按钮。

### 比赛管理 `/admin/fixtures`

功能：

- 搜索比赛。
- 查看 provider 原始字段摘要。
- 人工修改开赛时间、状态、比分、赛果。
- 标记延期/取消。
- 触发单场重新结算。

约束：

- 每次人工覆盖必须要求填写原因。
- 覆盖前后写 audit_logs。
- 已结算比赛被修改后，必须提示需要重新结算。

验收：

- 管理员能修正错误比分并重新结算。
- 审计记录能看到谁在何时改了什么。

### 参赛者管理 `/admin/participants`

功能：

- 创建人类参赛者。
- 创建 Agent 参赛者并绑定 AID。
- 签发 token。
- 撤销 token。
- 禁用参赛者。
- 查看该参赛者竞猜和积分记录。

验收：

- 至少 3 个 Agent 能拿 token 通过 HTTP 参赛。
- token 撤销后旧 token 立即失效。

### 同步日志 `/admin/sync-runs`

字段：

- job 类型。
- provider。
- 开始/结束时间。
- 状态。
- 读取行数/变更行数。
- 错误原因。
- payload hash。

验收：

- 能定位最近一次失败的同步任务。
- 能判断页面数据是新鲜的还是缓存的。

## 关键用户路径

### 人类用户首次参与

1. 打开首页。
2. 登录或使用管理员分配的账号。
3. 进入赛程页，筛选“可竞猜”。
4. 打开比赛详情。
5. 选择胜平负，填写可选比分和理由。
6. 提交成功。
7. 在“我的竞猜”看到记录。
8. 比赛结束后在排行榜看到积分变化。

验收用例：

- 给定用户未提交竞猜，且比赛未锁盘。
- 当用户提交主胜 2:1。
- 则系统保存该竞猜，显示可修改状态，并在列表标记“已竞猜”。

### Agent 通过 HTTP 参与

1. 管理员创建 Agent 参赛者并签发 token。
2. Agent 调用 `GET /api/fixtures?status=open`。
3. Agent 选择比赛并调用 `POST /api/predictions`。
4. Agent 调用 `GET /api/me/predictions` 确认。
5. 结算后 Agent 调用 `GET /api/leaderboard` 查看排名。

验收用例：

- 给定有效 token 和未锁盘比赛。
- 当 Agent POST 合法 JSON。
- 则返回 `ok: true` 和 prediction id。
- 当 Agent 用撤销后的 token 请求。
- 则返回 401，且不会写入竞猜。

### 管理员修正赛果

1. 管理员进入比赛管理。
2. 找到数据源赛果异常的比赛。
3. 查看 FIFA 官方页面或人工确认结果。
4. 填写修正比分和原因。
5. 保存覆盖。
6. 触发重新结算。
7. 查看 audit_logs 和 score_events。

验收用例：

- 给定比赛已结算但比分错误。
- 当管理员修改比分并重新结算。
- 则旧 score_events 不被重复累计，新总分按新比分计算，审计日志记录覆盖原因。

## 状态和错误文案

面向用户：

- `MATCH_LOCKED`：比赛已锁盘，不能提交或修改竞猜。
- `MATCH_NOT_FOUND`：比赛不存在或已被移除。
- `PREDICTION_NOT_FOUND`：未找到这条竞猜。
- `INVALID_SCORE`：比分格式不正确。
- `AUTH_REQUIRED`：请先登录或使用有效 token。

面向管理员：

- `SYNC_FAILED`：数据同步失败，请查看错误详情后重试。
- `PROVIDER_RATE_LIMITED`：数据源限流，请稍后重试或检查套餐。
- `SETTLEMENT_CONFLICT`：比赛数据变更，需要重新结算。
- `MANUAL_REASON_REQUIRED`：人工覆盖必须填写原因。

## MVP 验收清单

- [ ] 赛程页能展示完整赛事，不是手写少量样例。
- [ ] 比赛详情页能展示胜率来源和更新时间。
- [ ] 人类用户能提交、修改、查看竞猜。
- [ ] Agent 能通过 HTTP token 提交竞猜。
- [ ] 锁盘后网页和 API 都拒绝修改。
- [ ] 比赛结束后能结算积分。
- [ ] 排行榜展示总分、命中率、精确比分数。
- [ ] 个人页积分流水与排行榜总分一致。
- [ ] 管理员能看到同步状态和失败原因。
- [ ] 管理员能人工覆盖赛果并重新结算。
- [ ] 所有人工覆盖和积分变化可审计。
