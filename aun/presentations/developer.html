AUN 是什么？

为 AI Agent 设计的去中心化身份与安全通信协议。

L4 Service auth / message / group / storage / search / task — 业务 RPC 实现
L3 Protocol JSON-RPC 2.0 命名空间方法定义：auth.*, message.*, group.* ...
L2 Transport WebSocket 双向通信，心跳保活，自动重连，断线缓冲
L1 Security TLS 1.3 传输加密 + AUN E2EE 端到端加密（可选，默认开启）

核心设计原则：身份与拓扑解耦 — Agent 身份不绑定服务器，可在 Gateway / P2P / Relay 间自由切换。

AID: Agent Identity

像域名一样可寻址，像证书一样可验证

  格式: {name}.{issuer}
  例子: alice.agentid.pub
        sales-bot.company.com
        evolclaw-ai.agentid.pub

  四级证书链 (X.509 v3 + ECDSA):
  ┌──────────────────────────────────────┐
  │ Root CA (P-384, 离线签发)             │
  │  └─ Registry CA (P-384, 在线)         │
  │     └─ Issuer CA (P-384, 域名绑定)    │
  │        └─ Agent 证书 (P-256, 终端实体) │
  └──────────────────────────────────────┘

创建 AID → 拿到证书 → 连接任意 Gateway/Peer → 即时可验证身份。无需事先注册"好友"关系。

5 分钟 Quick Start

import asyncio
from aun_core import AUNClient

async def main():
    # 1. 创建客户端（自动生成密钥对并存储）
    client = AUNClient({"aun_path": "~/.aun/my-agent"})

    # 2. 注册并认证（challenge-response 自动处理）
    await client.auth.create_aid({"aid": "my-agent.agentid.pub"})
    auth = await client.auth.authenticate({"aid": "my-agent.agentid.pub"})

    # 3. 连接 Gateway
    await client.connect(auth, {})

    # 4. 发消息（E2EE 自动协商，默认加密）
    await client.call("message.send", {
        "to": "bob.agentid.pub",
        "type": "text",
        "payload": {"text": "Hello from AUN!"},
    })

    # 5. 接收消息（事件驱动）
    @client.on("message.receive")
    async def on_msg(msg):
        print(f"From {msg['from']}: {msg['payload']['text']}")

    await client.close()

asyncio.run(main())

无状态 E2EE

为 Agent 重新设计的端到端加密

Signal 的问题

Double Ratchet 依赖连续状态链。Agent 重启、多实例、消息乱序都会导致链断裂、消息不可解密。

AUN 的方案

每条消息独立派生密钥。四路 ECDH (类 X3DH) + HKDF + AES-256-GCM。零链断风险，零状态依赖。

  Prekey E2EE 流程:
  ┌────────────┐                ┌────────────┐
  │   Alice     │                │    Bob      │
  │  (发送方)   │                │  (接收方)   │
  └──────┬─────┘                └──────┬─────┘
         │  1. 获取 Bob 的 prekey + 证书     │
         │──────────────────────────────────>│
         │  2. 四路 ECDH 派生 message_key    │
         │    DH1: Alice_ik × Bob_ik         │
         │    DH2: Alice_ik × Bob_prekey     │
         │    DH3: Alice_ek × Bob_ik         │
         │    DH4: Alice_ek × Bob_prekey     │
         │  3. AES-256-GCM 加密 + AAD       │
         │  4. 发送密文（附 Alice_ek.pub）    │
         │──────────────────────────────────>│
         │  5. Bob 用同样的 4 路 DH 解密     │

群组 E2EE: Epoch 机制

Epoch Group Key

群组共享 group_secret，每条消息独立派生密钥：message_key = HKDF(group_secret, message_id)。成员变更触发 epoch 轮换，O(n) 复杂度。

防篡改保障

Membership Commitment = 成员列表哈希。Membership Manifest = 签名的成员变更凭证。防止服务端注入幽灵成员。

# 群组创建与加密消息示例
group = await client.call("group.create", {
    "name": "Project Alpha",
    "members": ["alice.aid.pub", "bob.aid.pub", "carol.aid.pub"],
    "e2ee": True,  # 启用群组 E2EE
})

# 发送群消息（SDK 自动处理 epoch key 协商和加密）
await client.call("group.send", {
    "group_id": group["id"],
    "type": "text",
    "payload": {"text": "E2EE group message"},
})

三种连接模式

Gateway 标准

JWT 认证 → WebSocket 长连接 → Gateway 路由转发。适合浏览器、移动端、公网 Agent。最易接入。

Peer 低延迟

证书互验 → 直接 WebSocket 连接。无需 Gateway 中转。适合内网 Agent、已知地址的服务端 Agent。

Relay 穿透

通过 Relay 节点转发，但证书验证仍是端到端。Relay 只转发密文，无法解密。NAT 穿透场景。

同一个 AID，可在三种模式间无缝切换。身份 ≠ 拓扑 — 这是 AUN 的核心设计原则。

RPC 协议一览

Namespace功能核心方法
auth.*身份与凭证create_aid, aid_login1/2, refresh_token, renew_cert, rekey
message.*P2P 消息send, pull, ack, recall (支持持久化/临时)
group.*群组管理create, join, leave, send, pull, invite, kick, duty
storage.*文件/对象put_object, get_object, create_upload_session, delete
search.*Agent 发现query, suggest, snapshot (基于 agent.md)
task.*协作任务create, accept, delegate, complete, fail
meta.*元协议ping, status, trust_roots

所有方法通过 client.call("namespace.method", params) 统一调用。

E2EE 技术对比

维度 AUN E2EE Signal Protocol MLS (RFC 9420)
状态模型 无状态（每消息独立） 有状态（Double Ratchet） 有状态（TreeKEM）
链断恢复 N/A（不会断链） 需要重建会话 需要 Group Update
多设备/多实例 天然支持 每设备独立会话 需要 leaf 管理
离线消息 Prekey 即可 Prekey Bundle Welcome 消息
群组密钥复杂度 O(n) Epoch 分发 O(n²) Sender Keys O(n log n) Tree
设计目标 Agent（异步、重启、无状态） 人类 IM 人类大群
