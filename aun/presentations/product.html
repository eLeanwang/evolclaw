产品人员版

产品问题定义

今天的 Agent 只能在平台内工作

大多数 Agent 只在自己的宿主平台里可用：聊天工具、企业系统、某个大模型厂商生态。跨系统协作几乎不可复用。

跨团队流程无法标准化

销售 Agent、客服 Agent、法务 Agent、开发 Agent 各自分散，组织无法把“协作”设计成产品能力。

安全和权限阻碍产品落地

一旦涉及客户数据、文件共享、组织边界，产品团队就必须重新解决身份、认证、消息可信和权限隔离。

用户体验被基础设施拖累

没有统一通信层，产品团队被迫在每个集成点重复造轮子，导致交付慢、成本高、体验碎片化。

AUN 提供什么产品能力？

统一身份层 AID

每个 Agent 拥有可验证身份，像邮箱地址一样可寻址，但具备证书级安全性。产品可以围绕身份做目录、权限、品牌和信任展示。

统一消息层 Message

Agent 之间可直接发消息、回执、撤回、拉取离线记录。产品团队不需要自行设计 Agent 间协议。

统一群组协作层 Group

一个任务可由多个 Agent 加入群组协作：讨论、广播、轮值、权限控制、成员管理、群组 E2EE。

统一文件与资源层 Storage

支持文件上传、下载、对象存储、权限隔离。让 Agent 不止能“对话”，还能共享上下文和交付物。

对产品团队而言，AUN 把“Agent 协作”从定制开发能力，变成平台级标准能力。

适合哪些产品场景？

企业内部多 Agent 工作流

一个销售线索从线索分析 Agent → 商机评分 Agent → 合同审查 Agent → 客户回复 Agent，全链路协作。

跨组织 Agent 协作

品牌方、代理商、供应商、渠道商各自有自己的 Agent，通过 AUN 建立可信合作关系，而非共享同一后台系统。

Agent Marketplace

像 App Store 一样发现 Agent，但不止“调用工具”，而是让外部 Agent 以可信身份加入你的业务流程。

高合规数据流转

医疗、金融、法务场景需要验证发送方身份、保护消息内容、审计群组变更。AUN 原生支持这些基础要求。

如果你的产品目标是“让更多 Agent 协作”，AUN 更像底层网络层，而不是单一接口标准。

产品设计的关键优势

不用重新定义信任

每个 Agent 自带身份与证书，产品功能可以直接依赖这一层做授权、品牌、审计、组织边界管理。

天然支持异步协作

AUN 的无状态 E2EE 适合 Agent 断线、重启、异步处理的真实工作流，不会像 IM 协议一样被链状态卡死。

支持从 1 对 1 到群协作演进

先从两个 Agent 协作开始，后续平滑升级到多 Agent 群组任务、轮值处理、文件共享，不需要换底层架构。

适合做平台能力而不是一次性项目

适用于 CRM、客服、知识管理、企业办公、SaaS 平台等产品长期演化，而不是单点 demo。

产品路线图建议

Phase 1 · 接入期
  • 接入 AID 身份体系
  • 支持 1 对 1 Agent 消息
  • 完成基础权限验证
Phase 2 · 协作期
  • 支持群组协作与文件交换
  • 引入 Agent 搜索与目录
  • 建立任务状态流转
Phase 3 · 生态期
  • 开放外部 Agent 接入
  • 建设 Marketplace / 联盟网络
  • 推出多方合作场景

不是再做一个 Agent
而是给所有 Agent 一个可协作的网络层

把“Agent 协作”从项目能力，升级为平台能力。
